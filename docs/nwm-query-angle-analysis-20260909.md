# 世界模型大转角查询的位置与处理链路

2026-09-09，接续实际预测可视化诊断。使用训练机现有环境、同一1800步模型和4条路线，新增记录所有有效查询、候选合并前几何及最终动作；没有改生产逻辑或训练。运行命令为 `CUDA_VISIBLE_DEVICES=0 bash scripts/rgb_only_optimization_runtime.sh server scripts/diagnose_nwm_navigation.py --output data/logs/nwm_call_diagnostic_20260909/geometry --max-samples 0 --checkpoint data/logs/ghost_concat_joint_bs8_20260908/train/ghost_concat_v1_joint_train/checkpoints/ghost_concat_v1_joint_train/ckpt.iter1800.pth`，退出0。环境版本同前一份诊断报告，结束后GPU回到43/16MiB。

## 核心结论

大转角主要来自“360度候选查询”和“最近前向移动的4帧上下文”之间的方向差。它是尚未执行的候选预测条件，不是智能体已经转过的角度，也不是相邻上下文帧的转角。候选可在侧后方；查询阶段不按当前前置相机的90度视野过滤，不会先朝候选旋转相机、再采集4帧后预测。

这4条路线全部有效查询为113个，其中50个（44.25%）超过90度。前一次展示的34个只是按顺序截取的图片子集，不能用其50%的比例代替本批全部查询比例。40次高层决策中有36次移动；其中31次选中目标具有当前有效查询，只有1次对应大于90度的查询角度。其余5次移动没有匹配的当前有效预测，不能将31作为全部移动次数。

本批没有源位姿错位：113个查询的当前与上下文末帧位置差全部为0，朝向差最大约4.44e-16弧度。候选合并会小幅改变角度，但没有出现“全部原候选≤90度，合并后却>90度”的查询。各原候选与合并目标的最大角度变化为12.59度。

## 当前上下文如何生成

1. 任务起点记录一帧真实前置RGB及位姿。
2. 当前 `back_algo=teleport`：每次选定ghost后，先移到该ghost关联的已访问前置节点。`teleport()`将朝向设为世界0度，同时清空旧世界模型上下文、记录一个新的锚点。即使前置节点就是当前位置，当前代码仍走该调用。
3. 控制器朝目标转向，再执行低级前进。只有`MOVE_FORWARD`对应的有效移动会加入上下文；单纯转向不会逐帧加入。碰撞导致没有水平位移的前进帧会被丢弃。
4. 保留最近4帧，不足4帧时跳过世界模型预测，不会复制最后一帧补齐。一般是最后4次移动，也可能含“新锚点+3次移动”。上一高层决策的历史不会越过teleport重置继续保留。
5. 每帧通过冻结DINO得到原始CLS和256个图块特征，按RAE统计量标准化，再以时间顺序打包成 `[4,257,768]`。世界模型接收的是这4帧特征及源到目标的最终相对动作条件，**没有额外接收每帧的绝对位置/朝向序列，也没有接收12方向全景**。

本批36个上下文就绪的决策点中，有3个上下文包含明显不同朝向。162度例子的4帧朝向为 `[0°,120°,120°,120°]`：第一帧是teleport产生的0度锚点，后3帧为朝120度的移动画面。其他两个为 `[0°,-120°,-120°,-120°]` 和 `[0°,-30°,-30°,-30°]`。这种人工重置锚点与连续行走历史不同，是值得独立验证的输入分布差异；这不是已确认的索引错位，也不能仅凭3个点认定其造成预测失败。

## 候选位置与朝向如何确定

导航路点预测器读取12方向全景，方向划分为120格（每格3度），得到候选方向和距离。代码将方向统一为逆时针角度。设当前世界位置为(x,y,z)、当前朝向为ψ、候选相对方向为a、距离为d，理想候选位置为：

```text
x_target = x - d * sin(ψ + a)
y_target = y
z_target = z - d * cos(ψ + a)
```

这一步是几何外推，不是让智能体实际走过去后记录的终点。训练中另有模拟行走的真实终点用于监督，但当前世界模型查询明确取图中最终ghost均值，并非那个真实终点。

图中处理顺序为：在0.5米匹配范围内先匹配已访问节点，匹配上的候选不作为新ghost查询；再匹配未访问ghost，合并同一地点的多次位置观测；否则新建ghost。合并后查询最终平均位置，同一ghost在本步只查询一次。本步没有重新观测到的历史ghost不会自动全部重新查询。

**目标朝向是“从当前实际位置看向最终平均目标位置”的方向**。随后保留这个绝对目标朝向，将平移和转角改用上下文末帧作为参考。因此即使出现当前与上下文末帧不同的情况，也不能把源简单替换后重新改变目标视角。本批二者完全一致。

转角最终折返到[-180°,180°)，+162度表示左转162度，-131度表示右转131度；不是把345度误报成大转角。平移归一化为“前向米数/0.2497589/64”和“左向米数/0.2497589/64”；转角仍用弧度，不除以π。时间条件为 `clip(水平直线距离/0.2497589, 1, 64)/128`，不计入转弯、障碍绕行或实际路径长度。

## 查询目标和实际到达位姿不是完全相同

查询阶段使用理想位置和连续角度；实际执行时先teleport到选定前置节点、朝向归零，再以15度为单位转向，以0.25米为单位前进。前进次数使用向下取整，碰撞/滑动还可能改变到达位置。因此即使所有坐标计算都一致，真实控制终点也可能偏离查询位姿。

在31个可与下一决策位姿对应的选中查询里，到达与查询的位置差平均0.185米、朝向差平均3.21度。这里比较的是本批对应动作的实际终点，并不是可直接归因于某一个控制因素的独立实验。

实际选中的144度例子尤其直观：源世界朝向180度，理想目标朝向324度；执行先归零，再量化转到330度，实际到达(4.3351,0.1716,-2.4290)。相对查询目标的位置误差0.266米、朝向误差6度。因有teleport归零，查询相对角度144度不能直接等同于底层实际执行的转向动作角度。

此外若选中ghost的关联前置节点不是当前位置，执行源也可能不同于此次查询源。上述31个匹配样本的选中前置节点均为当前节点，因此本批没有测出这种额外差异，不能从代码可能性推断它已发生。

## 对问题的判断

- 已解释的大转角主因：全景候选覆盖身后，而世界模型查询共享当前4帧前向上下文。合并和角度折返不是本批大转角的主因。
- 新发现值得隔离验证的因素：teleport每次清空历史并加入0度锚点；理想查询与15度/0.25米控制终点不完全一致；时间条件只表示直线距离。它们是具体的语义/分布差异，尚不能宣称是导航下降的因果根源。
- 不应直接删除身后候选：部分任务确实需要回头，且大转角查询大多未被选中。查询量不等于执行转弯量，也不等于这些预测造成了错误决策。
- 若进一步改接口，应优先固定同一批导航查询，比较按候选方向采集的真实多帧上下文与当前前置上下文；这要求真实获取对应方向的历史图像及正确的相机位姿，不能只把转角设成0或旋转特征冒充。控制终点对齐、去除人工锚点应分别验证，不混在一次训练里。
