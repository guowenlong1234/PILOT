# 全景训练后续性能审查

审查日期：2026-09-09。对象：`perf/panorama-training`，提交 `9de664d`，笔记本工作区 `/home/sia/project/ETP-R1-perf`。本轮是源码审查，没有运行新基准、修改训练实现或启动训练。以下优先级是试验顺序，不是已经测得的耗时排名。

## 现状与判断

应以 `configs/nwm/direct_context_fast.yaml` 的 direct/FP16/64/64 路径为下一轮基线。已有报告记录双 A6000、每卡四环境、12 次更新去掉两次预热后为 12.105 秒/更新；同轮 front 为 10.637 秒/更新。这是历史短测，不是本轮测量，也不包含正式保存开销。扩大 DINO 批次在此前 FP32 对照中没有独立收益，不建议继续盲目加大批次。

剩余机会主要是冻结世界模型里的重复计算、导航注意力计算方式，以及环境/双卡等待。当前是在线采集轨迹的训练循环，不能套用离线 DataLoader 增加 worker 的办法解决主要等待。

## 建议优先试验

### 1. 一次世界模型预测内缓存不变的条件计算

证据：`vlnce_baselines/nwm/raenwm_core/models.py:650` 的 `_prepare_inputs` 每次模型前向都重新处理四帧 `x_cond`、位置编码、动作 `y_emb`、相对时间 `span_emb` 和 `c_dyn`。采样循环反复调用同一模型，但这些输入在一次查询批次内不变。`CDiTBlock.forward` 还反复计算每层的 `norm_cond(x_cond)`。

建议将上下文嵌入、动作/时间跨度嵌入、融合后的静态条件和各层上下文归一化提到采样循环外，缓存只活在本次预测中。保持原精度和操作次序。不要把完整交叉注意力的键/值直接跨采样步复用：`shift_ca_xcond`、`scale_ca_xcond` 受当前采样时间影响，调制后的上下文会变；噪声状态、采样时间嵌入和当前帧特征也必须每步重算。

这是最值得先做固定输入回放的方向，但可缓存部分占整个世界模型的比例仍需测量，不能承诺总训练提速百分比。

### 2. 导航注意力改用合并计算接口

证据：`vlnce_baselines/models/etp/ETP_R1_vilmodel_cmt.py:128` 和 `:346` 仍显式生成注意力分数矩阵，再执行 softmax、dropout 和第二次矩阵乘法。常用图交叉注意力调用在 `GraphLXRTXLayer.forward` 中仅消费输出 `[0]`。

建议对不需要返回分数且无特殊 head mask 的路径使用 PyTorch `scaled_dot_product_attention`，减少中间矩阵读写；保留需要分数的旧接口回退。必须保留图距离偏置、文本/图节点掩码、训练 dropout 和全遮挡行语义。该接口能否采用更快的 GPU 内核取决于 dtype、尺寸和 mask，不能保证自动使用 Flash 内核。

验收不仅比较前向，还应比较反向梯度、有限性和短训练损失。世界模型的交叉注意力已经设置 `need_weights=False`，不要把这条已有优化作为新收益。

### 3. 重叠环境渲染与视觉编码

证据：`low_level_context.py:637` 已把请求按环境分组并使用 `envs.call`，并不是逐环境 `call_at` 渲染；但主进程等待整组图像返回并 `np.stack` 后，`panorama_runtime.py:191` 才开始逐批 DINO 编码。不同环境渲染量不一致时，先完成的图像也在等待。

可尝试按环境/图像块返回结果，先完成的部分先编码，并预分配图像缓冲区以减少复制。需要确认 Habitat 通信接口是否支持安全的异步读取，不能直接给现有连接加多个读线程。分块过小可能增加通信与编码调用次数，收益必须用端到端结果判断。

`ss_trainer_ETP_R1.py:3548` 的 `get_navigation_state` 已合并当前状态与候选几何/目标距离查询；候选数据依赖本步路点预测，不能简单把整个调用移到上一步。进一步合并消息前先测它的实际阻塞时间。所有异步改动必须保持历史编号、reset/pause 索引、图像顺序和模拟器状态恢复语义。

### 4. 融合层梯度按桶合并通信

证据：`ss_trainer_ETP_R1.py:1072` 的 `_synchronize_raenwm_rgb_fusion_gradients` 按参数逐个 `all_reduce`，在每次更新反向之后调用。融合 MLP 的多个参数可按设备/精度合为一个或少数几个连续缓冲区通信，减少小通信启动成本。

保持缺失梯度补零、两卡平均和混合精度缩放/反缩放次序。它主要减少通信调用开销，无法消除两卡轨迹长短不同造成的等待；预期应低于前两项，实际收益待测。

## 次级与长训练专项

- **已有但未启用的 Euler 最终状态采样器**：`raenwm_core/RAE/src/stage2/transport/integrators.py:151` 提供 `sample_final`；当前 `configs/nwm/raenwm_mp3d_fresh_cls.yaml:21` 为 `final_only_euler: false`。可独立比较它与通用 `odeint` 的同步/中间状态存储成本。保持时间网格、步数、噪声及运算次序；这是既有数值合同的一部分，不能未经回放验证直接翻开关，也不能把它等同于减少采样步数。
- **冻结 DINO 不请求全部层输出**：`rae_dinov2_encoder.py:289`、`:328` 开启 `output_hidden_states=True`，实际只使用 `last_hidden_state`。可关闭中间输出以减少引用持有和峰值显存；Transformer 各层仍要执行，速度收益预计小。检查是否存在外部 hook 对完整输出的依赖。
- **日志同步小项**：`ss_trainer_ETP_R1.py:3941` 的 `loss.item()` 在反向之前取 CPU 标量，可延迟到更新后的统一统计。当前梯度累积为一，通常每更新只有一次，不应当成主要瓶颈。非零梯度保护通常先检查很小的末层 bias，不能为省这一点成本直接删除保护。
- **保存长尾**：基础 ghost 配置每 200 步保存完整恢复状态。所有 rank 采集环境 iterator 状态后，rank 0 在 `ss_trainer_ETP_R1.py:1580` 顺序写模型和训练状态；已有后台传送不等于后台保存。可在一致时点创建独立 CPU 快照后由单个后台写任务落盘。不能把会被 optimizer 修改的 `state_dict` 引用直接交给线程，必须保持模型/优化器/RNG/iterator 同一步并成对完成发布。测量快照时间、写盘时间、内存峰值及断点真实恢复。现有基准明确禁用 `save_checkpoint`，12.105 秒不包含这项成本。

## 验证顺序

1. 使用已有 direct/FP16/64/64 基线，在训练机对应工作区及实际训练环境进行短时间 CPU/GPU 时间线分析；区分世界模型、DINO、环境等待、导航前向/反向和通信。分段强制同步只作定位，不用作最终吞吐结果。
2. 先逐项尝试静态条件缓存、导航合并注意力；其次比较最终状态采样器、通信合桶，再决定是否值得改异步渲染。每项都用相同输入和噪声单独验收。
3. 保留四帧历史、全部候选、朝向精度、采样时间网格、训练参数和优化器设置。验证固定查询质量与梯度后，再重复多组双卡短跑；报告秒/更新、环境步数、预测查询/编码图像数、两卡等待和显存。
4. 最终增加覆盖至少一次真实保存的试验，以累计墙钟时间评估长训练收益。数值或执行路径变化的优化还需导航验证，冻结世界模型质量通过不能替代完整导航指标。

不优先继续增加 DINO 批次，不因冻结而期望免除世界模型前向，不把旧编译试验当作已通过方案；E24 关闭路径的 replay/smoke 审计也不应算作当前热点。
