# 按查询方向选择历史全景上下文：方案分析

状态：2026-09-09方案建议，尚未实现或运行新世界模型预测。本次只读检查现有上下文、候选查询、全景编码和检查点接口，并对已捕获113个查询做几何计算。

后续核查修正：真实75k世界模型没有独立帧时间/顺序编码，固定条件和噪声仅倒序4帧，预测余弦0.99995；单次float32前向验证顺序置换不敏感。下文关于“倒序让模型看到前进运动”的解释应改为虚拟轨迹的几何语义，不能当作现有网络已经感知时序的事实。最新具体算法采用目标位姿固定、目标朝向全景视图、虚拟参考源和条件重算，见[虚拟轨迹算法](nwm-virtual-trajectory-algorithm-20260909.md)。

## 推荐方案

保留最近4个实际时间点的全景观测；对每个目标位姿选择一条朝向目标的4帧相机序列，仍然向现有世界模型输入4帧、每帧257个特征。世界模型结构不需要因此改成多相机模型。目标位置和绝对目标朝向始终不变，改变的是观测相机的方向及相对动作坐标系。

第一版建议复用现有12个、间隔30度的相机方向。以末帧目标转角选择最近的相对相机偏角，并在4帧中使用同一个偏角。这相当于给机器人固定安装一台朝左、朝后等方向的虚拟相机，读取它的4帧历史；同一序列不因扇区边界反复切换相机。

例如旧查询的末帧朝向120度、目标朝向282.46度，旧相对转角162.46度。选择相对机体偏转150度的相机，末帧相机朝向270度，新相对转角12.46度；目标仍然是原位置、朝282.46度看到的画面。该目标的新局部平移约为前方1.436米、左侧0.317米，原来则为后方1.402米、左侧0.443米。角度和平移必须一起换算。

## 目标位姿与坐标合同

先独立确定不可变的目标 `(p_target, yaw_target)`，再选择上下文。目标朝向可继续沿用当前“实际当前位置指向ghost均值”的定义；未来若改为预计实际到达朝向，应单独形成另一项实验。

对4帧机体位姿 `(p_i, yaw_i)`，选择统一的相对偏角φ：

```text
φ = 最近的30度倍数，使 wrap(yaw_target - yaw_last - φ) 最小
每帧相机朝向 = yaw_i + φ
输入图像 = 该时刻、该相机朝向的真实90度透视图
source = 最后选定图像的真实相机位姿
新转角 = wrap(yaw_target - source.camera_yaw)
新平移 = 将 p_target - source.position 投影到 source 相机的前/左坐标轴
```

然后沿用当前平移尺度、RAE标准化和目标图块/CLS输出接口。本方案中末帧位置不变，所以第一轮对照保持距离时间条件不变；不能因为改变相机方向就把时间改成负数。

若12方向均可用，最近方向的末帧角度误差上界为15度，4方向则为45度。这是几何性质，不是预测质量保证。既有113个有效查询的离线换算如下：

| 观测方向数 | 最大绝对剩余转角 | 平均绝对剩余转角 |
|---|---:|---:|
| 4（间隔90度） | 45度 | 21.45度 |
| 12（间隔30度） | 15度 | 7.95度 |

## 为什么第一版不逐帧独立挑最近方向

在机体转动时，逐帧选择“最接近绝对目标朝向”的离散相机，可能在扇区边界跳变30度。现有世界模型没有额外接收4帧各自的姿态序列，隐含在视觉中的转向可能变得不连续。同一相对偏角保留原时间序列的朝向变化，是易核验且便于复用现有相机的第一版。

一种后续方案是4帧均使用同一绝对世界朝向，甚至完全等于目标朝向。这样相机不随机器人转身而改变朝向，相对目标转角可为0。但通常需要从保存的全景原图按相机内参做真实透视重投影，再编码；不能简单剪下全景长图拉伸，也不能旋转/插值DINO特征假装得到新视角。重投影只能使用历史真实相机已经覆盖的光线，应检查完整视野和图像边缘覆盖。

这两种序列的运动分布不同，应分别诊断；不能把“同一相对偏角”描述成“四帧固定世界朝向”。前者也不会自动消除现有teleport锚点与后续帧之间的机体朝向跳变。

## 保存与计算

当前高层决策点已有12方向全景编码，但低级移动上下文只有前置RGB；不能声称改一个索引就完成，也不能用4个高层决策的全景代替4个低级时间点而不承认时间尺度改变。需要让低级上下文保留对应时刻的全景RGB及相机位姿。

建议使用最近4帧的小缓冲区，每帧记录时间/段ID、真实位置、机体朝向、各相机外参、全景原图和可选的冻结DINO原始特征缓存。按“帧ID+相机方向+编码器/统计版本”缓存，按需批量编码；本步多个候选使用同方向时，共享4帧上下文编码。已有高层全景只有在时间、位姿、相机方向、预处理与精度兼容时才复用。

4帧×12视角×224×224 RGB的uint8原图约6.89MiB/环境；对应257×768特征用FP16缓存约18.07MiB/环境。这只是缓存本身，不含模型、编码中间结果和传输成本。若全方向全部编码，低级上下文DINO图像数量最多约为当前12倍，不能把新增成本只描述为几十MiB内存。优先先根据本步候选确定实际需要的方向，只编码这些方向，并把所有所需帧组批。

每个ghost仍然只有一次世界模型查询，不对12方向分别预测再投票。世界模型输入仍为 `[候选数,4,257,768]`；历史可以保存全景，但每次只抽出一条4帧序列。4张同一时刻的不同方向图不能当作4个历史时间点补齐。

## 仍须处理的限制

1. 小相对转角不等于熟悉的历史运动。机器人向前走、相机朝后看时，会形成“倒退观看”的画面变化；原训练数据主要跟随行走方向，这种新上下文也可能偏离训练分布。需要用真实查询对照验证，必要时用真实多视角导航序列微调世界模型。
2. 可见性和遮挡仍存在。侧后相机提供更多已有证据，不能保证观察到墙后的目标内容。
3. 现有teleport会中断物理运动连续性，仍应保持分段；不能把瞬移前后的位姿硬拼为连续四帧。0度锚点是否保留、是否改为首个真实移动朝向，应作为独立因素验证。不足四个实际时间点时回退到纯观测导航。
4. 理想目标与离散控制终点的差异并未被本方案消除，应另做目标位姿对齐对照。
5. 保存的必须是已经观测位置上的全景，不能在未到达目标点渲染真值给策略。本项目模拟器的历史重放仅可重建已访问位姿的合法观测；真实机器人要在经过时实际采集并保存。

## 最小验证顺序

先保持世界模型、目标位姿、噪声、采样步数和时间条件不变，用同一批实际导航查询做三组预测：旧前置上下文、4方向选取、12方向选取。先重做已定位的162度样本，再扩展多个场景的预先分层样本；同时报告预测与真值、所选源视图与真值的CLS/图块相似度，避免把“新源画面本身更有用”完全归功于世界模型。

若12方向明显改善预测，再评估冻结当前导航权重时的直接替换，明确这是输入分布变化的诊断；随后以相同预算训练适配模块/联合策略，才比较正式导航SR、SPL与耗时。仅压低角度本身不构成成功。

实现主要涉及 `low_level_context.py` 的事件载荷与缓存、`environments.py` 的历史全景采集、`runtime.py` 的多视角缓存、`etp_adapter.py` 的逐查询选视角及源坐标变换。应新增上下文格式标识、相机布局、选择规则及重置语义到checkpoint元数据中；现有单视角检查点不能被默认为相同训练状态直接续训。世界模型主体和ghost拼接融合维度可保持兼容。

这是一项可独立实现、可通过同目标对照验证的接口改进，当前尚未验证性能收益。

## 补充：身后目标使用倒序上下文

用户提出可以将身后目标的上下文倒序。建议将其作为与选视角配合的候选路径：先获得朝目标方向的真实历史相机视图，再将图像、位置、相机朝向、帧ID同时倒序。前向移动时，后向相机看到的是远离场景；倒序后可以形成接近场景的视觉变化，可能更接近世界模型熟悉的前进序列。只倒放原前置画面不会自动让目标转角变小。

最重要的接口变化是末帧源位姿：`[p0,p1,p2,p3]`倒序后变成`[p3,p2,p1,p0]`，世界模型参考源是p0，不再是实际当前位置p3。必须保持目标位置和绝对朝向不变，根据p0及该图像的相机朝向重新计算全部平移、转角、距离时间条件，不能沿用p3的条件。时间条件不能仅因数组倒序就机械取负；若将其作为朝目标延伸的虚拟前进轨迹，按新的源到目标关系构造正向跨度。若目标与该延伸方向不相容，则不使用这条倒序上下文。

初版候选选择可考虑12相机偏角×正序/倒序共24种组合，利用位姿计算筛选，不需要运行24次世界模型。先检查四帧来自同一连续段、无人工朝向突跳，目标对新末帧具有合理的前向位移、较小目标朝向差且距离处于有效范围；再比较历史移动在所选相机前轴上的方向，倾向选择前进而非倒退的序列。方位小并不能代替平移/历史运动检查。最后仅对选中的一组上下文运行一次预测；没有合格序列时保留纯观测导航。阈值与排序仍需验证，不能从本批数据推出最优规则。

对已有样本只做位姿计算的结果：

- 样本0原始右转131.41度，4帧机体朝向均为-15度。使用相对偏角-120度的侧后相机后，目标转角变成-11.41度；正序历史的每步相机前向位移为-0.125米，倒序后变成+0.125米。末帧源变为原最早位置，源到目标距离由1.101米变为0.826米。这个例子支持检验倒序方案，但尚未重新渲染侧后上下文或测量预测质量。
- 样本19的4帧朝向为`[0,120,120,120]`，含人工锚点。固定偏角150度后直接倒序，相机朝向为`[270,270,270,150]`，最后一帧跳回150度，目标转角反而从12.46度增加为132.46度。应拒绝这种不连续序列，或在另一项方案中利用完整全景构造固定世界朝向的四帧；不能为倒序方便而悄悄改变目标朝向。

倒序序列仅使用已经观察到的图像，因此不需要未来真值。在静态MP3D环境里有较清晰的几何解释；在动态物体、光照或非刚体变化场景下不能假设倒放与真实反向运动等价。世界模型本身也不保证时间可逆，效果需要固定目标与噪声做“前置正序 / 选方向正序 / 选方向倒序”对照验证。
