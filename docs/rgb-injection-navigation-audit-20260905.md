# RGB 注入导航效果排查与下一轮实验建议

核查时间：2026-09-05 09:53–10:00，Asia/Shanghai。下文进度是核查时快照。

## 结论

目前没有证据证明 RGB 注入在 ETP-R1 上不能提高性能，但也没有证明它带来了稳定、可归因的提升。最优先的工作是区分两件事：继续训练是否损伤了原有导航能力，以及预测特征本身是否提供了有用信息。

本次核查发现：

1. 修复前的低级上下文实验存在已确认的导航 CLS 适配层梯度丢失；修复后的正式训练正在正常运行，尚未评完。
2. 当前注入门在训练中迅速接近全开；同一时期验证表现没有稳定超过起点。需要检查注入强度和底座共同更新，不能只增加训练步数。
3. 低级上下文会被每个高层动作的 teleport 清空，实际是局部移动末尾的四帧；旧高层方案是多个导航决策之间的历史。低级模式候选注入覆盖率反而更高，因此不能把失败简单解释为“没有执行注入”。
4. ETPNav 的历史提升是 57.8032% → 59.1082%，即 +1.3050 个百分点；当前起点已经是 63.7303%。两者世界模型、CLS 生成方式、门初始化、上下文和训练批量并不完全相同。
5. 同一批 1,839 条路线的配对核查显示，旧高层最佳点修好 128 条、损失 119 条，净增只有 9 条；当前修复后最佳点修好 113 条、损失 117 条。主要现象是修好一些路线的同时破坏另一些路线。

本次只读检查远端进程、配置、结果和日志，未启动新训练/全量评测，未停止任务，未修改远端代码或模型。只在笔记本补充调查文档。

## 3. 为什么 ETPNav 的收益不能直接复制

已阅读笔记本 `/home/sia/project/ETPNav` 的 `research.md`、迁移记录、当前 RGB adapter，以及 `fb95fa4` 保存的原始 31 点结果表。历史核心实现提交为 `37ac145`。

| 项目 | ETPNav 历史收益实验 | 当前 ETP-R1 修复后实验 |
|---|---|---|
| 无 WM 起点 | `iter13800`，SR 57.8032 | `iter14200`，SR 63.7303 |
| 峰值 | `iter17400`，SR 59.1082 / SPL 49.6767 | 当前新增 1000，SR 63.5128 / SPL 53.7450 |
| 预训练 | R2R 预训练 `model_step_87500.pt` | 联合预训练所选 `model_best_step_465000.pt` |
| 世界模型 | patch-only `step70000` + 外置 token/confidence heads | 原生 CLS+patch `step75000` |
| 上下文 | 高层导航正前方 latent | 低级 MOVE_FORWARD RGB，teleport 清空 |
| 门提示 | 外置头预测的 confidence | 观测/预测 CLS 余弦一致度 |
| 门初始偏置 | -8，sigmoid 约 0.000335 | 0，sigmoid 为 0.5 |
| 全局训练 batch | 单卡 8 | 双卡各 8，共 16 |
| 选点 | 31 点中挑最佳 | 当前修复后已完成 19 点 |

两个 adapter 的基本公式相同，但“相同网络公式”不等于“相同实验”。旧 ETPNav 从无 WM 起点到峰值的净提升为 24 条路线；其 31 点 SR 平均 56.4420%，最终 `iter20000` 为 57.6944%。它证明存在一个值得复核的较好 checkpoint，尚不能把全部 +1.3050 点归因于 RGB 注入，因为没有同预算不加注入的继续训练对照。

高层上下文来自真实已观测画面，不等于偷看目标或真实未来画面。在当前低级输入合同下运行高层模型是设置不一致，但高层结果本身不是因为“高层”这个名字就变成真值泄漏。两种上下文可以作为独立研究设置比较，不能把高层成绩标成低级成绩。

## 4. 代码与日志揭示的具体问题

### 4.1 已确认的旧梯度错误已修复，不能解释所有新结果

提交 `ea860aa` 把低级同步改为 `forward_raw_cls_and_patch_latents`，避免在 no-grad + autocast 缓存中预先执行可训练导航 residual MLP。真实训练增加了非零梯度硬检查。9 月 4 日已有逐 checkpoint 参数审计；本次连续运行到 `iter5000`，没有触发该检查。

这说明现在不宜继续把新实验表现统称为“梯度没修好”。梯度正确只证明参数在学，不保证学习方向能提高未知场景导航表现。

### 4.2 注入门趋于全开，而不是可靠性选择器

本轮训练日志的窗口统计：

| 新增步数 | 门均值 | 门标准差 | 注入变化 L2 均值 | 候选注入覆盖率 | 观测/预测余弦均值 |
|---:|---:|---:|---:|---:|---:|
| 200 | 0.500 | 0.000 | 0.026 | 81.2% | 0.466 |
| 1000 | 0.543 | 0.009 | 0.157 | 81.5% | 0.419 |
| 2000 | 0.925 | 0.036 | 1.546 | 81.5% | 0.468 |
| 3800 | 0.987 | 0.012 | 2.764 | 81.6% | 0.443 |
| 5000 | 0.994 | 0.008 | 3.412 | 81.3% | 0.441 |

门值接近 1 且方差很小，是值得优先验证的现象；不能单靠它证明注入错误，因为 residual 本身仍可选择性输出零。日志也没有原始特征范数，因此目前不能把 L2=3.412 描述为特征的某个百分比，更不能直接判为“过大”。下一步应增加 `||fused-raw|| / (||raw||+eps)`、分候选/距离/场景统计，并进行强度消融。

初始 residual 末层是零，因此门初始为 0.5 不会在第零步直接混入一半预测。与 ETPNav 的区别在于训练开始后的梯度尺度和注入增长速度。门改回 -8 也不是已验证答案；旧 patch 迁移中沿用旧式门仍没有稳定提升。

### 4.3 底座与新模块同学习率一起更新，缺少保持原有能力的约束

`ss_trainer_ETP_R1.py` 把 policy 与 RGB adapter 放入同一套 AdamW 参数组，学习率都是 `1e-5`；本轮无预热、预热后最小比例 1，即恒定学习率。初始化是从干净 `base_iter14200.pth` 只加载模型权重，再建新的优化器；这不是从错误低级 checkpoint 续训。

教师动作采样不是始终 75%。实际公式为 `0.75 ** (floor((新增迭代+14200)/3000)+1)`，起始约 23.73%，到新增 5,000 附近约 13.35%。这个进度已显式承接旧导航迭代，不是忘记设置偏移；不建议未经对照再重置为 75%。

逐路线结果已经显示大量“修好与破坏同时发生”，但缺少无注入、同预算继续训练对照，尚不能确定其中多少是底座继续训练造成的漂移。

### 4.4 低级上下文的真实信息范围

当前 `IL.back_algo=teleport`。`R1Env.step(act=4)` 在 `back_path is None` 时先调用 `teleport(front_pos)`，而 `teleport()` 无条件 `reset_trace()` 并记录落点锚帧。即使这次是回到当前前端节点，也执行这条路径。之后仅成功前进产生的新画面进入上下文，最多保留末尾四帧，不足四帧不补齐。

训练统计中 `nwm_context_reset_events` 与 `nwm_context_environment_count` 每个窗口都相等；`iter5000` 两者均为 5.204，支持每次动作边界都清空的解释。名义每步约 0.25 m，四个相邻前进观测通常只覆盖约 0.75 m 的局部范围。低级上下文就绪比约 70%，按候选加权的注入覆盖率约 81%；它与高层旧模式约 62%–64% 的覆盖率不是同一个分母。

因此低级模式同时改变了输入连续性、空间跨度、重置频率、注入覆盖率；原高层实验全局 batch=8，而低级为 16。现有实验不能把效果差异单独归因于高低级上下文。

不要直接删除所有 reset：真正的瞬移与朝向重置会造成不连续。若做上下文改进，先记录位姿跳变和实际移动路径，只在证明连续时保留上下文；或者在训练数据中复现当前的重置/锚帧模式。不能为了提高覆盖率把不连续轨迹伪装成连续运动。

### 4.5 同为 768 维，不代表已完成导航特征对齐

`R1Policy.py` 的 `cand_rgb` 实际来自 `nav_cls = raw_cls + cls_residual_mlp(raw_cls)`；`rgb_fusion.py` 虽把它叫作 `raw_rgb`，它已经经过导航适配。

原生 NWM 的 `pred_cls_raw` 则仅反归一化回 DINO 原始 CLS，未经过该导航适配。因此当前公式为：

```text
观测导航特征 = h(当前画面原始 CLS)
delta = 预测原始 CLS - 观测导航特征
输出 = 观测导航特征 + gate * residual(delta)
```

这与现有设计文档一致，不是本次发现的代码违约，但有额外学习负担：residual 同时处理当前视角与预测目标视角的差异，以及原始 CLS 与导航 CLS 的差异。建议单独对照 `h(预测原始 CLS)` 后再融合，或使用独立的小型对齐层；是否提高导航尚未实测。

当前余弦 0.42–0.47 比较的是“当前位置朝候选方向的图像特征”与“目标位置预测特征”，还混合了上述适配差异。它不是预测与同位姿真值的精度。不能拿它与 RAE-NWM 历史 CLS 真值余弦 0.8532 直接比较，也不能当作预测可靠性标签。

历史 native CLS 模型的 time 图像选点报告使用 50 步 Euler，本项目部署为 10 步；离线指标优良不保证在当前上下文、候选距离、朝向和 10 步推理下同样优良。应在实际导航查询分布上核查，而不是优先重训整个世界模型。

## 5. 建议按这个顺序做

所有方案均是下一轮建议，本次没有启动或改动正在运行的实验。

### 第一轮：用已有 checkpoint 判断问题发生在哪里

固定修复后 `iter1000`，保持 NWM 查询、噪声、上下文、候选映射和导航网络完全相同，只改变最终 residual 的乘数：`alpha=0, 0.25, 0.5, 1`。其中 alpha=1 已有完整结果。另在同一测评机、当前代码、8 环境下复跑原始 `base_iter14200`，作为跨平台/代码版本的参照。

建议先在固定调参子集筛选，最终选定设置再做全部 1,839 episode；不要反复在完整 val_unseen 上搜索几十个系数后只报最高点。所有结果使用独立命名，明确这些是消融覆盖参数，不是原配置原样复测。

- alpha=0 明显优于 1：当前注入项在这个已训练模型上拖后腿，优先限幅/对齐/可靠性。
- alpha=0 和 1 都低于原始起点：优先测试底座继续训练的影响，不应直接认定预测完全无用。
- alpha=1 优于 0 但仍低于起点：注入可能在补偿继续训练损失；需要冻结/小学习率底座的实验。

alpha=0 的训练后模型不是原始基线，因为底座已经共同适应注入；必须同时保留原始基线和下一轮无注入训练对照。实现时保留相同查询与全景前向路径，仅在最后乘零，以免随机数消耗和代码分支变化污染归因。

### 第二轮：最小的训练对照

固定同一 `base_iter14200`、低级上下文、全局 batch=16、教师采样进度、数据/随机种子、训练预算和选点规则，比较：

| 编号 | 训练方式 | 解决的问题 |
|---|---|---|
| A | 不加 RGB 注入，底座继续 SFT 2,000 次 | 单独测继续训练是否损伤起点 |
| B | 冻结底座，仅训练 RGB adapter 2,000 次，adapter lr=1e-5 | 测预测是否能在保留原能力时提供增益 |
| C | 从 B 的独立开发集所选点开始，底座 lr=1e-6、adapter lr=1e-5，短程共同微调 | 测温和适配是否优于全网同速更新 |

B 可先使用当前门初始化以隔离“冻结”变量，再依据第一轮结果选择一个较保守设置，例如 `alpha=0.25` 或初始偏置 -4；不要第一次就同时更改对齐层、门、batch 和上下文。C 是新增优化方案，与 A/B 总预算不同，最终方法比较需要补齐相同总更新次数的对照。

冻结底座意味着参数冻结、dropout 等行为固定，但仍需允许导航计算把损失梯度传回 adapter；不能把整个 policy 前向包在 `no_grad()` 中。新的分组学习率与冻结模式应有显式配置，并相应调整只适用于“导航 CLS 层可训练”场景的梯度检查，先做单/双卡真实更新验收。

主要选择标准：SR 提升同时 SPL 基本保持，并减少基线成功路线被破坏的数量。确定一个有希望的配方后，做至少 3 个训练随机种子的确认，并按场景报告结果；不能把连续 checkpoint 当作独立重复。

### 第三轮：如果注入仍然没有独立收益，再修预测输入/输出

先在训练场景采集实际导航候选查询及同位姿真值特征用于诊断，单独留场景验证。记录上下文跨度、是否刚重置、候选距离、转角、候选估计位置与实际可达位置的偏差。使用冻结原始导航 policy，避免每种预测方案更换采样轨迹。

优先检查三组小对照：

1. 预测 CLS 先过冻结导航映射 `h`，再注入；与当前直接注入原始 CLS 对比。
2. 10/20/50 步 NWM 在相同初始噪声、相同查询上的 CLS 真值误差；若 10 步是主要损失，再考虑加步数或训练小模型补偿。
3. 同一低级上下文下，比较预测目标 CLS、最后一帧 CLS、当前候选方向 CLS；另做训练时不用预测内容、仅同容量观测适配器的对照。这样才能判断收益来自预测信息，还是多了参数/继续训练。

若预测目标 CLS 不优于简单替代项，优先训练面向导航查询的小型 CLS 对齐/可靠性头；若真值预测明显更好而导航仍不提升，再改注入位置或训练目标。可把指令信息、距离/转角、预测不确定性接入门，但先验证现有门是否能区分成功与失败候选。

真实未来观测只用于离线训练标签和诊断上界，不作为最终评测策略的输入。不要把同当前位置的相似度高误认为预测准确；目标画面变化大的候选可能恰好最有信息量。

只有上述检查表明 native CLS 模型在导航查询分布上确有瓶颈，再考虑世界模型训练中的 CLS 单独损失权重、查询分布适配或重训。当前本地 transport 实现对元素均匀求 MSE；CLS 只有 257 个 token 中的一个，值得做分项质量监控，但不能仅凭这个比例断言它没有学会预测。
