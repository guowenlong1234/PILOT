# 从持久候选状态一阶段迁移到 E24 二阶段

核查日期：2026-09-16。本次为源码、配置和已有产物分析，没有启动训练或修改运行代码。ETPNav 工作区及产物只读；保留笔记本现有未提交修改。

## 结论

建议采用“冻结当前一阶段 → 用实际预测链采集新决策数据 → 离线训练 E24 → 完整导航验证 → 必要时增量采集再训练”。可复用 E24 网络与离线损失，但不能直接启动旧 E24 joint 脚本。当前代码明确禁止 ghost_concat 与 E24 同时开启，且世界模型历史上下文接口尚未打通。

这里的一阶段指已完成的 `ghost_concat_persistent_compiled_10k_20260911`，不是早期图文预训练，也不是原始普通 SFT。

## ETPNav 当时的真实流程

主要依据为 ETPNav 的 `docs/stage0-final.md`、`docs/e24-joint-sft.md`、冠军 YAML、离线采集/训练源码和训练机数据盘产物。

1. 冻结 `rgb17400` 导航基座，包括当时的视觉融合路径。在环境中运行并保存决策，而不是对静态图片单独训练分类器。
2. 每个决策从可执行候选节点中取基础分数最高的5个，保存完整候选分数、候选对应关系、语言特征、候选节点特征、几何信息、教师动作和有效掩码。
3. 旧离线冠军使用真值未来观测：从候选q0沿通往真实目标的最短路径前进1.5米，借助模拟器 Oracle 获取q1图像，再由冻结编码器提取 CLS 和图块特征。Oracle 在这里指能查询真实未来信息的仿真接口，不是部署时可用的预测能力；不仅未来图像是真值，未来位置选择也使用了目标信息。
4. 特征写成离线分片，训练时只读取缓存，只更新 E24。远端旧 train coverage 为84,839行决策、407,279个未来槽位，未来有效率87.20%；验证有15,937行，STOP隔离后的主要决策评价为13,757行。
5. E24 为每个 Top-5 候选产生有界分数修正，修正后仍与全部可执行候选比较。基础策略决定 STOP 或继续移动；E24 只重排移动候选。
6. 冠军由中心17250附近三份模型权重平均得到；旧在线配置再使用 `clamp(1.206 * delta, -1, 1)`。1.206是旧数据校准值，不能直接作为新工程最优值。

旧冠军配置 `configs/experiments/r2r/stage0_g59_top5_offline_e24a_e22b_seed2.yaml`：768维、8个查询向量、12个注意力头、3轮独立融合、FFN3072、dropout0.1；AdamW学习率2e-5、权重衰减0.01、batch32、最多20000次更新、梯度裁剪10、每250步保存、seed2。

它的实际损失为：

`L = 0.25 L_signed + L_ghost_CE + 0.5 L_pair + 0.001 L_delta² + 0.05 L_absent_noop`

含义依次是：修正方向正确、最终移动候选选对、教师候选排在竞争者前、不产生过大修正、教师不在Top-5时避免无根据改动。正确/错误基础决策的 CE 与配对损失权重实际为2/1；不要拿代码类的默认值代替冠军配置。STOP样本按旧决策规则排除，分类分母包含全部有效移动候选，不是只包含Top-5。

旧离线开发集报告净修正+295个决策，约+2.14个百分点；它不是完整导航成功率提升。后续另有从13800基座出发的联合 SFT 和 DINO-CWP 预测链 pilot，不能与这个离线冠军混为同一训练过程，也不能把文档中的历史未运行状态当作所有后续工作均未运行。

| 数据管线 | ETPNav 的 collector、offline_dataset、训练/验证/平均工具可作参考 | ETP-R1尚无对应完整离线采集训练闭环；数据字段及来源清单要按本工程重建 |
| 阶段冻结 | 当前有冻结导航及模型审计能力 | 新增冻结完整stage1、只训E24的独立模式，不能借旧joint开关模拟 |
| 权重及恢复 | 当前已有严格哈希、保存/恢复机制 | 新阶段只载入stage1权重；新优化器和步数；保存新格式及上下文来源 |

已直接核查的阻断点：

- `ss_trainer_ETP_R1.py:1052`：ghost_concat 显式要求 E24 关闭；`:868`：新的全景上下文也要求 E24 关闭。
- `nwm/runtime.py:478`：`source_context_snapshot()` 对非front模式直接报错。旧候选缓存依赖这个接口，因此删除上面两个检查不能解决问题。
- `active_lookahead/candidate_q0.py:141`：旧实现每环境共用一份源快照；当前 `panorama_runtime.py:156` 则按查询目标选择历史视角、顺序及源位置，快照需要按实际查询保存。
- `ss_trainer_ETP_R1.py` 的旧 E24 模式要求融合层可训练，与“冻结完成的一阶段”冲突；旧参数组恢复数量也写死，必须重新定义阶段所有权。
- `joint_e24.py:151` 的旧初始化强制旧离线avg3格式及其三个来源步数。新训练头应支持新产物和从零初始化，不能伪造旧来源清单。
- `joint_e24.py:682` 的原生 CLS 联合损失在完整 logits（含STOP）上做 CE，但执行动作走 `online_e24.py:23` 的 STOP 隔离。新冻结二阶段应沿用移动候选决策损失，明确处理STOP/教师缺失行。

## 推荐的新链路

`真实观测与指令 → 冻结stage1更新持久候选状态并评分 → Top-5 → 复用各候选q0预测图块 → 冻结DINO-CWP提出q1 → 冻结世界模型预测q1特征 → E24修正 → 全部移动候选比较`

q0是候选到达位置，q1是从该候选进一步前瞻的位置；q1只用来评价候选，不是立即执行的导航点。E24输出不写回一阶段持久节点状态，避免两个机制混在一起。

上下文迁移不能把一阶段切回旧front模式。建议第一版为每个q0保存生成时的实际历史token、位姿、顺序、目标朝向、源位置、归一化及版本信息；q1沿用该冻结上下文，显式计算新目标条件。q0朝向必须取实际预测记录，不能用旧“当前朝向加相对转角”的假设重建。跨步缺失或过期缓存只使该槽无效，不悄悄补算q0。

上述“q1沿用q0上下文”是建议的新合同，尚未实现或做质量验证；若改为对q1重新选择历史视角，必须另立合同与对照，且只能使用已观测历史位置。禁止去q1渲染真实图像或用真实可达性筛选模型提议来冒充无Oracle预测。

主训练数据应来自当前预测链，不能直接复用ETPNav旧分片。旧分片的节点/语言特征、分数、Top-5、几何和未来特征都来自不同基座或未来查询方式。真值未来仅保留为独立诊断组，用来区分“评分头学不会”和“世界模型给的信息不够”。

先只训练E24；导航策略、持久融合层、视觉/语言编码、世界模型和DINO-CWP全部冻结，冻结模块保持eval模式。旧Top-5 CLS adapter先不作为必需项；如确实需要，再做“E24+adapter”的独立对照。新建头末层零初始化，让初始行为与冻结stage1一致。旧冠军权重可另作热启动对照，不预设它更好。

## 为什么不直接重跑旧联合训练

本工程8月的原生CLS联合训练已经完成10000步、50点全量测评，历史记录显示所有点SR/SPL均未超过14200基座。E24动作翻转后期通常只有0.1%—0.4%，修正幅度和adapter梯度也明显缩小。该历史事实与本轮尚未训练的新二阶段分开看待。

已发现的相关差异包括旧真值future有效率约87%而在线预测约47%、旧q0位置合同不一致、STOP训练/执行口径不一致，以及基础策略同时学习相同教师信号。这些说明新实验应先隔离E24贡献，不足以证明某个单一因素就是全部退化原因。

## 实施顺序与验收

1. 固定一个stage1检查点及完整配置，建立同机stage1-only基线、资产哈希和全冻结张量清单。
2. 新增stage2独立模式及全景q0快照合同，完成真实小轨迹验证：零残差动作一致、q0不重复预测、q1不查询真实未来、历史缓存跨步及reset/pause正确。
3. 用R2R train采集小分片，验证字段、有限值、教师Top-5覆盖率、q0缓存命中、CWP none、q1有效率；训练若干batch并跨进程恢复，审计只有E24变化。
4. 完成正式train缓存及独立开发缓存，离线训练。旧2e-5/batch32/最多20k步可作为起始配置，最终按新数据规模及开发曲线选点；不预先固定17250、三点平均或1.206。
5. 记录修正正确数、破坏正确数、净收益、动作翻转率、残差幅度、future有效率、教师覆盖率及运行成本。验证集只用于选点和诊断，不能混入训练。
6. 对少量候选模型完成R2R val_unseen 1839条完整导航，与同机stage1-only逐episode比较。离线决策收益不能代替SR/SPL收益。
7. 若离线改善而闭环无改善，优先用当前组合策略重新采集训练状态，只更新E24，处理动作改变导致的访问状态差异；确认独立收益后再考虑小学习率联合微调。

本次没有进行运行测试；结论依据静态实现和已存在的训练/测评记录。实际训练机器尚未由本轮指定；若沿用最近stage1部署，应在训练机 `etpnav_unified` 与本项目自有运行时验证，测评机仍使用专用容器/环境。实施前再核查驱动状态、GPU占用、源码版本，不沿用历史进程号。
