# RGB-only 三步优化执行记录

目标：完成源位姿修复、已有 5200 检查点强度消融，以及 A/B/C 各 2000 次训练和完整导航评测。用户于 2026-09-07 明确授权使用训练机、测评机资源并调用子 agent。本文为执行记录，实验尚未全部完成时不代表最终性能结论。

## 固定实验设计

- 共同基线：`pretrained/active_lookahead/base_iter14200.pth`，SHA-256 `1694b175d913404bfef8a53519d6f405db5de7f8b051e8343700125e43f05c61`。
- E24 全部关闭。世界模型、统计文件及 DINO 底座沿用原 native CLS 方案。
- 训练 A：不使用世界模型，导航全网继续 SFT。
- 训练 B：冻结导航底座及其 dropout，只训练 RGB 注入模块。
- 训练 C：与 B 相同，并将预测 raw CLS 通过同一个冻结导航 CLS 适配层。
- A/B/C 均为单卡、16 环境、全局 batch16、2000 次更新、每200保存；lr=1e-5、原教师采样偏移14200、seed100。三组统一单卡是资源调度选择，不直接与历史双卡实验作严格单变量比较。
- 固定检查点评测1000和2000，不根据中途峰值增加选择次数。
- 已有5200消融：同一测评机、8环境、1839条，旧源位姿alpha1用于复现桥接；修复源位姿后alpha=0/0.25/0.5/1。alpha0仍执行世界模型和双全景路径。
- 原始基线无WM，需要禁用低级上下文采集；这不启用高层世界模型，只是使用无采集的旧兼容设置。
- 所有最终评测在测评机专用容器和环境完成；对应模型随训练原子同步。

## 已完成的正确性验证

- 源位姿相关：两机各46项测试通过。合成回归覆盖碰撞仅转向、位置偏差、目标绝对朝向保持、无差异情况和旧行为开关。
- 冻结/融合/性能与checkpoint针对性测试：两机各97 passed、1 skipped（禁用CUDA的CPU测试）。
- 训练机更广泛CPU测试：521 passed、2 skipped；3项仅适用于测评机部署环境的测试在训练机因路径/Python环境不适用失败。随后在测评机正确环境运行整个对应文件，17 passed。
- 真实B/C单卡两步训练通过：643个导航张量逐元素不变，注入末层真实更新；非零梯度分别约0.033/0.029。
- B双卡、每卡8环境、4次真实更新通过，完整checkpoint审计确认382,197,481个导航参数全部不变、编码器元数据不变、注入模块更新。
- A/C单卡16环境4步通过。A热身后约5.5秒/步；C热身后约28秒/步。正式耗时以长任务实际日志为准。
- 测评机base/旧源5200/修复源5200各单环境单episode预检通过。第一条路线不是碰撞错误发生率的代表样本。
- 原始基线checkpoint此前未在测评机固定路径保留，已经训练机—测评机专线复制，SHA-256一致后原子发布，没有复制回笔记本。
- 预检遇到的基线文件命名解析和WM关闭时低级采集冲突已修复，失败记录保留在独立smoke目录，不混入正式结果。

## 资源与托管

训练机两张RTX A6000各48GB，测评机现场实际为RTX3090 24GB。检查时无其他GPU计算任务，受保护ETPNav容器停止；未修改、停止或借用受保护工程/环境。

训练机GPU0有限队列：A→C，GPU1：B（先完成C短模型加载评测验收）。测评机单一有限队列：base→legacy→a0→a025→a05→a1→A1000/2000→B1000/2000→C1000/2000。缺失检查点等待原子同步，每次30秒检查，单文件最长48小时；异常退出后保留manifest与日志。

默认产物根：两机各自工程中的 `data/logs/rgb_only_optimization_20260907/`。

- `train_gpu0_queue.log`、`train_gpu1_queue.log`：训练机托管队列日志。
- `eval_queue.log`：测评机托管队列日志。
- `train/<实验名>/manifest.json`、`run.log`、`checkpoints/<实验名>/`：命令、代码版本、hash、模型及训练状态。
- `eval/<实验名>/manifest.json`、`results/<实验名>/eval_results/`：完整指标、逐episode指标和源位姿统计。
- `audit/`：冻结权重、参数约定、配对结果与环境核验。

子进程由独立session托管，SSH退出不会停止；没有改变实际训练命令语义。数值库线程池限制为1，避免多个Habitat进程各开数十个CPU线程。训练机正式Python3.10.14，测评机3.11.15；两机PyTorch2.2.2+cu121、Transformers4.49.0、Habitat/Habitat-Sim0.3.3，CUDA构建12.1。每个任务日志重新打印实际版本。

## 核心代码与复核工具

- `vlnce_baselines/nwm/etp_adapter.py`：用上下文末帧位姿计算预测条件，保持目标绝对朝向；`condition_source_pose=query_current`显式复现旧行为。
- `vlnce_baselines/ss_trainer_ETP_R1.py`：冻结、对齐与检查点合同；保存每个评测点完整源位姿统计。
- `scripts/rgb_only_optimization.py`：固定训练/评测参数、资源锁、结果验证、恢复与等待同步。
- `scripts/audit_rgb_frozen_checkpoint.py`：CPU逐张量冻结审计及元数据约定核验。
- `scripts/summarize_rgb_only_optimization.py`：核验1839条ID一致性、配对SR/SPL、救回/损失和共同成功路径变化。

当前源位姿统计的queries分母是“上下文足够的候选查询”，不等于episode数、高层动作数或全部请求数。位置发生偏差时，修复同时影响平移、朝向、时间条件与记录中的源到目标距离；应描述为源位姿整体修复。
