# 面向目标位姿的虚拟轨迹构造算法

2026-09-09。用户提出将后向全景历史倒序，并一并重定义时间，使世界模型接收正向虚拟轨迹。本文件给出具体算法及当前模型适用边界。尚未实现全景新链路；本次只执行了真实权重上的上下文顺序诊断。

## 先修正对当前世界模型的理解

重新直接检查 `raenwm_core/models.py` 和75k EMA发现：4帧只使用重复的、不可训练的二维空间位置编码，没有独立帧编号或每帧时间戳；各帧编码后拼成一组供预测特征查询的上下文，注意力没有时间顺序遮罩。在固定动作、目标时间跨度和噪声时，对这些帧整体重排，数学上不改变注意力结果。

训练机真实样本0实测：仅倒序4帧，完整预测特征余弦0.9999549、CLS余弦0.9999800；随机重排完整特征余弦0.9999827。单次float32速度场前向，正/逆序最大差5.72e-6、平均差8.79e-7、余弦1.0。低精度10步采样的倒序最大差0.519、平均差0.00527，不能称逐元素相同；差异符合有限精度下累积数值路径变化，不能据此当作模型理解了倒序运动。对应JSON为 `diagnostics/nwm-call-20260909/context_order_audit.json`。命令在训练机现有工程环境执行，退出0，严格加载314键，未训练或修改生产实现。

因此，应修正上一版“倒放可以让当前模型读到前进运动”的表述：**倒序可以定义新的几何参考端点和一致的虚拟轨迹语义，但当前模型没有显式区分帧序。效果主要来自新视图、新参考位姿和正确的新目标条件。**这不否定虚拟轨迹方案，但避免把收益归因于模型并未接收的时间信息。

## 一、不可变的目标

为每个导航候选先确定：

```text
Target = (episode_id, ghost_id, graph_revision, target_position, target_yaw)
```

位置和朝向必须在上下文选择前固定。第一版沿用原查询目标定义；不能换参考源之后再用新源到目标的连线修改目标朝向。世界模型输出仍绑定这个Target，导航实际位置、图历史和候选身份不因虚拟轨迹而改变。

## 二、历史缓存

保留同一连续移动段的最近4个全景时间点；需要更多可选窗口时可增加至8帧，第一版不必增加。每帧记录：

```text
frame_id, real_step_id, segment_id, actual_position,
body_yaw, camera_extrinsics, panorama_RGB, feature_cache
```

必须是已访问位姿实际能获取的全景。场景或episode切换、瞬移位移跳变都切段；从不跨段构造虚拟轨迹。瞬移后的起点位置可作为新段第一点，但图像朝向必须用所选真实相机外参，不能把front图像的yaw=0直接改标成其他角度。

## 三、统一相机观看方向

算法上更整齐的完整方案：对每个目标选择一个固定的世界观看朝向β，4个历史位置均读取朝β的90度透视图。β可以等于目标朝向，令最后相机到目标的朝向差为0；也可以对β按30度量化，令误差≤15度并便于跨候选复用。

对于原先朝向为 `[0,120,120,120]` 的机体轨迹，只要各时间点已保存合法全景，都可以提取朝270度的4张真实视图。得到的相机序列是 `[270,270,270,270]`，人工body yaw=0不会变成图像突然转向。此方案只统一相机朝向，不修改历史位置，不跨越真实瞬移段。

实现前提是正确的透视重投影：从保存的多相机RGB及内外参取样所需光线，并检查覆盖有效性，再重新编码DINO。不能直接旋转CLS/图块特征，也不能把全景长图拉伸到224方图。若先做最小实现，可使用前一版的固定机体偏角12视角缓存，但需拒绝由机体转动导致的大朝向跳变；该简化版与固定世界β不是同一个合同。

## 四、构造正向或反向虚拟轨迹

对一个连续4帧窗口 `(p0,p1,p2,p3)`，枚举：

```text
F = [(p0,I0β), (p1,I1β), (p2,I2β), (p3,I3β)]
R = [(p3,I3β), (p2,I2β), (p1,I1β), (p0,I0β)]
```

无论F还是R，新的虚拟时间均定义为 `[-3,-2,-1,0]`，最后一帧为源位姿S，目标定义在虚拟时间h。原物理时间仅用于缓存可追溯性，不传给世界模型。对应时间坐标变换可写作 `τ = σ(t - t_source)`：正序σ=+1，倒序σ=-1。若原帧间隔不等，不能仅改编号就声称等间隔；初版保持原低级移动采样，不再另行稀疏抽帧。

倒序后的S是p0，不是实际当前位置p3。算法必须显式返回 `source_frame_id/source_pose`，不能让下游重新读取机器人当前位姿作为源。

当前世界模型没有输入四个τ的接口，所谓重新计时体现在序列的构造语义和源到目标跨度 `rel_t=h/128` 上。不是把原 `rel_t` 的符号直接取反；更不是倒转流匹配采样器的积分方向，后者是另一种时间变量。

## 五、几何可行性与选择规则

给定β，定义水平相机前向单位向量 `fβ=(-sinβ,-cosβ)`，对应世界(x,z)平面。令虚拟轨迹位置为q0…q3，目标为p*，源S=q3。

```text
历史各步前进量 ui = dot(q[i+1]-q[i], fβ)
目标前向距离    u* = dot(p*-S, fβ)
目标朝向差     δψ = wrap(yaw_target-β)
```

先筛选：4个时刻同段且图像覆盖有效，位移连续；虚拟历史总体前向、没有明显反向步；目标位于源前方；目标朝向差小；源到目标距离和横向偏移位于事先约定的范围。只检查δψ小不够，可能相机朝对方向但目标仍在源后方。

第一版采用确定性字典序，避免设计未经验证的加权分数：先比较上下文前进方向与目标延伸是否一致，再比较目标相对方位/朝向偏差、源到目标距离，最后以时间较新的源打破平局。几何阈值应在诊断开始前固定并记录，不在完整验证集上反复挑选。

最简单的直线后方目标通常选择R：后置画面在物理正序中是倒退运动，在虚拟R中成为前进运动，目标也位于p0前方。若目标恰好位于原4个位置之间，F/R都可能缺少合理的“继续向前”关系；应换一个合法历史窗口或不注入预测，不能用正数时间掩盖位置关系不一致。

## 六、动作与时间条件的精确构造

对所选末帧相机朝向β、世界位移 `Δx=x*-xS, Δz=z*-zS`：

```text
forward_m = cosβ*(-Δz) + sinβ*(-Δx)
left_m    = -sinβ*(-Δz) + cosβ*(-Δx)
dx_norm   = forward_m / 0.24975892673356762 / 64
dy_norm   = left_m    / 0.24975892673356762 / 64
dtheta    = wrap(yaw_target-β)   # 弧度
```

初版继续用现有近距离查询时间估计，但必须从新S重算：

```text
h = ||p* - S||水平 / 0.24975892673356762
rel_t = h / 128
```

h是估计的虚拟前进帧数，不是现实时间流逝。初版限定在训练允许的正向范围（1–64）内，对低于最小跨度或超过上限的候选明确回退，而非默默裁剪后假装与位移完全一致。沿用距离估计仍不是严格还原训练时间；如果改成曲线长度或中位移动速度估计，应独立对照，不同时改多个因素。训练原数据支持正/负目标跨度，但本方案优先只构造正向虚拟查询，不要求关闭模型的负时间能力。

## 七、批量推理接口

```python
for target in current_targets:
    candidates = []
    for window in continuous_windows(history, length=4):
        for order in (forward, reverse):
            seq = make_geometry_sequence(window, order)
            beta = choose_target_aligned_world_yaw(target.yaw)
            if geometry_is_valid(seq, beta, target):
                candidates.append((seq, beta))
    selected = choose_by_geometry(candidates)
    if selected is None:
        continue  # 该候选保持纯观测图输入
    views = get_cached_real_perspective_views(selected)
    tokens = encode_normalize_pack(views)  # [4,257,768]
    action, rel_t = condition_from(selected.last_camera_pose, target)
    batch.append(tokens, action, rel_t, target.id, selected.source_id)

predictions = frozen_world_model(batch)   # 每个目标只预测一次
scatter_prediction_by_target_id(predictions)
```

选择在渲染/编码之前进行，几何枚举不触发多次世界模型调用。同一帧/世界朝向β只生成和编码一次。若固定世界β需重投影，缓存键还需包含投影内参、精度和编码器/统计版本。策略融合、输出CLS含义和目标位置不变。

## 八、实验如何拆分

本次已完成“固定所有条件，仅置换4帧”的诊断，确认当前结构的顺序不敏感。下一轮应明确拆成：

1. 旧前置上下文、原源位姿；
2. 目标方向上下文、原源位姿；
3. 同一组目标方向图像、按几何选择新源位姿并重算条件；
4. 仅当需要研究真正的运动时序，再给模型增加帧时间/相对位姿编码并训练，而不是给冻结模型凭空加未训练的时间标记。

前三组固定目标位姿、世界模型和随机噪声，比较预测CLS/图块与目标真值，记录源到目标距离变化。第三组改变源条件是算法的一部分，不能把它的收益全部称为“倒序收益”。跨场景预测诊断通过后，再验证导航融合和耗时。当前方案没有实测性能保证。
