# 精确方向直接渲染、大批次与混合精度验证

用户授权继续在 `perf/panorama-training` 独立工作区优化，允许直接渲染、更大的世界模型/DINO 批次和混合精度。原长训练保持停止，本轮只运行基准与质量验证。

最终推荐：**直接渲染 + DINO 批次上限 64 + 世界模型批次上限 64 + FP16 定向编码**。12 步双卡验证为 **12.105 秒/更新**，相比上一轮全景优化版 **17.871 秒**耗时下降 **32.27%**，吞吐提升 **47.64%**；同轮旧 front 基线 **10.637 秒**，仍慢 **13.79%**，没有完全追平。

## 实现

每次低级动作结束后，环境保留最近四个已访问位姿，并发放单调递增的历史编号。候选目标生成后，主进程按目标计算绝对朝向，汇总并去重缺失的“环境编号、历史编号、朝向”，每个环境一次批量请求所需图像；不再预渲染十四方向全景，也不再从全景插值取图。

渲染端只接受当前历史表中的编号，不接受客户端位置作为渲染依据。reset 清空历史，旧编号失效；pause 后按当前环境索引路由。现有光心校验和位姿恢复保留，并检查渲染没有改变模拟器观测状态或动作计数。目标朝向和正序/倒序参考端点仍按 `world_exact_select` 计算，四帧使用同一个目标绝对朝向。

新增配置：`panorama_observation_source=cube/direct`、`panorama_visual_precision=float32/fp16/bf16`；DINO 和世界模型批次分别沿用 `panorama_encode_batch_size`、`panorama_prediction_batch_size`。默认旧配置不变，推荐配置通过覆盖文件显式启用。

为隔离批次变化的影响，世界模型随机噪声固定按原来的八行分组生成，再交给执行批次。单元测试验证不同执行批次下每个查询的噪声和生成器最终状态一致。直接渲染/精度/噪声分组写入检查点上下文元数据；不允许用不匹配的上下文合同静默续训。

## 逐项吞吐

训练机双 RTX A6000，沿用 14200 基座、每卡 4 环境、总批量 8，策略学习率 2e-6、融合层 1e-5；世界模型仍为原 75000 权重、原十步采样。以下各运行 6 步、剔除第一步、启用相同分段同步计时。

| 路径 | DINO 上限 | 世界模型上限 | 定向编码精度 | 秒/更新 |
| --- | ---: | ---: | --- | ---: |
| 上一轮优化后的全景插值 | 16 | 8 | FP32 | 16.641 |
| 仅改直接渲染 | 16 | 8 | FP32 | 13.244 |
| 扩大世界模型合批 | 16 | 64 | FP32 | 11.747 |
| 再扩大 DINO 合批 | 64 | 64 | FP32 | 11.771 |
| 再使用混合精度 | 64 | 64 | FP16 | 10.842 |
| 旧 front 参照 | 原历史批次 | 当前有效查询整批 | 原混合精度 | 9.969 |

直接渲染的六步 rank 0 定向图像请求为 2168 张，原全景路径额外渲染 9758 张；当前全景预渲染计数为零。DINO 大批次在 FP32 下未显示独立吞吐收益，不能宣称批次越大越快。这里的 64 是上限，实际输入取决于本步有效候选和缓存命中。

## 预测质量

复用既有冻结的 11 场景、22 个 episode、83 个决策片段，共 288 个目标。新独立渲染器先对每个片段的四张原生方向图像进行校准，与原采集图像最大像素差全部为 0。

将多个片段的目标合并为预测批次以实际覆盖大于八行的输入。每个目标按稳定 ID 和噪声种子生成相同噪声，各方案共享；目标真实图像只用于评分，不输入历史视图提供器。六场景的 162 个开发目标用于精度选择，预先规定优先 FP16，只要 CLS/图块余弦相对 direct FP32 的场景均值下降不超过 0.005；开发集达标后锁定，另五场景 126 个目标用三组噪声复核。

下表为复核集场景等权结果，378 个目标—噪声对；余弦越高越好，RMSE 越低越好。

| 配置 | CLS 余弦 | 图块余弦 | CLS RMSE |
| --- | ---: | ---: | ---: |
| 全景插值 FP32，16/8 | 0.826675 | 0.704895 | 0.559249 |
| 直接渲染 FP32，16/8 | 0.829367 | 0.707958 | 0.554794 |
| 直接渲染 FP32，64/64 | 0.829393 | 0.707956 | 0.554724 |
| 直接渲染 BF16，64/64 | 0.829381 | 0.707954 | 0.554762 |
| **直接渲染 FP16，64/64** | **0.829386** | **0.707941** | **0.554764** |

FP16 大批次未显示预测质量下降。该结论是固定输入的世界模型质量验证，不是完整导航 SR/SPL 验证；与插值版不要求逐元素相等，也没有降低角度精度、减少预测目标或缩短世界模型采样步数。

## 使用与产物

最终复测各运行 12 步、剔除前两步预热、关闭分段同步，以两卡较慢的平均更新时间计。旧 front 与新方案的优化器分组、参数量和学习率相同。新方案实际 DINO 最大批次达到 64，世界模型每次有效候选最大为 17/18，因此在这些调用里全部一次合批；“上限 64”不表示每次填满 64。

两卡审计均通过：冻结视觉骨干、路点预测器、世界模型的参数哈希不变，CLS 残差映射及融合层参数发生更新，损失和梯度范数均有限。PyTorch 峰值分配约 11541/10783 MiB，不包含全部模拟器显存。最终运行记录为 `final_front/`、`final_fast/` 与 `final_summary.json`。

最终回归为 **567 passed、3 skipped、2 warnings**；另外 GPU 相关历史/像素检查 **13 passed**，均退出 0。配置保护会拒绝与底层 RGB 编码器显式精度冲突的组合，推荐保持基础配置中的 `RGB_ENCODER.precision=ambient`，由定向分支独立选择精度。CLI 新参数也完成 dry-run 验证。

推荐覆盖配置：`configs/nwm/direct_context_fast.yaml`，在 `run_r2r/iter_train_rae_dino_ghost_concat.yaml` 之后合并。该配置按训练机双 A6000、每卡四环境验证；没有在测评机重新运行本轮性能基准。

正式训练/测评入口 `scripts/ghost_concat_job.py` 新增可选参数：

```text
--observation-source direct --visual-precision fp16 --dino-batch 64 --nwm-batch 64
```

不传这些参数时保留旧默认命令，避免给既有实验 manifest 增加无关覆盖项。入口原有工作区限制仍然有效，本独立工作区使用专门基准入口。
