# RxR 训练吞吐优化（2026-09-20）

## 最终结论

最终采用：**双卡，每卡12环境、累积1次，总批量24；冻结视觉编码器编译；省去DINO中间层输出；异步有限值检查；并行教师动作查询；导航网络中间结果重算。**

**教师动作采样概率及衰减计划保持原样。** 起点为0.75，衰减间隔5000步、偏移0、归零阈值0.15。教师动作查询并行化只改变执行方式，不改变采样概率；相关一致性测试覆盖了动作、随机数状态及STOP/无候选分支。

最终同机50次更新、排除前2次预热的复测结果如下：

| 指标 | 原配置 | 最终保留配置 | 变化 |
|---|---:|---:|---:|
| 导航动作/秒 | 45.986 | 54.739 | **+19.03%** |
| 采样路线/秒 | 3.513 | 4.129 | **+17.52%** |
| 秒/更新 | 6.832 | 5.813 | **-14.91%** |
| 整卡峰值显存，GPU0/1 | 26958 / 28407 MiB | 23829 / 26394 MiB | 最终最高约25.8 GiB |
| 计时窗口GPU-util均值，GPU0/1 | 61.93% / 62.12% | 60.96% / 59.51% | GPU-util不能替代吞吐指标 |

两组退出码均为0，两卡50次优化器更新均成功，缩放因子保持16384、增长计数50；冻结参数不变、映射层真实更新、损失有限的审计全部通过。GPU-util分别为每卡161/137个采样点的均值，采样窗口仅包含第3—50次更新。

此前未开启导航重算的组合达到26.85%动作吞吐提升，但峰值显存约46.0 GiB；最终选择19.03%的方案，将显存余量扩大到约22 GiB。最终数据为训练机结果根目录的 `selected_comparison.json`，原始结果在 `final_baseline/` 与 `final_selected/`。

包含环境初始化、首次编译、预热及审计的整次命令耗时为387.04秒与377.08秒。上表是稳定计时窗口的吞吐收益；增加环境和首次编译有启动成本，不能把稳定吞吐提升当作短任务端到端加速比例。

原长训练已停止，最新2200步模型及训练状态完整保留。本次没有恢复长训练。

## 最终保留的实现

| 项目 | 作用与边界 |
|---|---|
| 每卡6环境×累积2次 → 每卡12环境×累积1次 | 总批量仍24，减少一轮采样及前后向调度；场景分组、随机数消费和分组损失归一化会改变 |
| RGB和深度编码器编译 | 固定图像尺寸，批量维度动态；不增加包装子模块，不改变模型参数键名 |
| 不保留DINO中间层输出 | 减少无用的中间张量；单独开关该项时最终token逐位一致 |
| CUDA流上的有限值检查 | 保留非有限值检测，省去每次前向都等待CPU读取检查结果；异常由CUDA同步点报告 |
| 跨环境并行教师动作查询 | 保留原候选随机选择顺序和教师内部状态更新规则；该项单独加速很小，不宣称明显独立收益 |
| 导航中间结果重算 | 反向时重算导航子网络，减少长期保留的激活；保留随机数状态，仅在训练且启用梯度时生效 |

入口：

- `run_rxr/iter_train_rae_dino_sft_fast.yaml`
- `scripts/manage_rae_rxr_sft_fast_server.sh`，支持已有的 `start/resume/status/logs/stop` 管理方式。
- `vlnce_baselines/models/encoders/compiled_visual.py`：冻结视觉模块的编译实现。
- `MODEL.checkpoint_navigation=True`：导航中间结果重算。

正式学习率1.5e-5、目标30000次更新、预热1000步、每200步保存、原教师采样曲线、轨迹上限25、图像尺寸及视场角、四语言guide `_90` 训练集均沿用原任务。编译存在小幅浮点舍入差异，不能称作逐位等价训练，也不据此宣称导航精度提升。

## 测试条件与计时方法

训练机：两张RTX A6000 48GB、NVLink互联；环境 `etpnav_unified`。实际版本：Python 3.10.14、PyTorch 2.2.2+cu121、CUDA运行时12.1、Transformers 4.49.0、Habitat/Habitat-Sim 0.3.3、驱动580.178.04。未修改环境包，未使用测评机资源。

所有性能对比固定使用75%教师概率，从原2200步模型权重和相同随机种子开始；各试验重新创建优化器，短测预热为1步。这是独立性能测试，并非原训练的精确恢复。正式配置的预热仍为1000步。

基准入口：`scripts/run_rxr_throughput_benchmark.sh`、`scripts/benchmark_rxr_throughput.py`；顺序扫描入口为 `scripts/run_rxr_throughput_sweep.py`。每次试验排除前2次更新，计时包括环境推进、前向、反向和优化器更新，不保存模型检查点。以两卡较慢rank的用时为分母，统计两卡合计导航动作数；同时报告采样路线数和更新耗时。路线吞吐包含达到轨迹上限后结束的采样，批量变化时不能只比较秒/更新。

所有表内任务均退出0、计时区间内优化器更新成功。8、10、14、16环境均没有超过保留的12环境重算方案。11环境未重算方案略快，但会改变总批量；最终选择保留24总批量并显著降低显存的12环境重算方案。

未重算导航的12环境方案还做过50次更新对照：45.986 → 58.334动作/秒（+26.85%），6.832 → 5.436秒/更新（-20.42%），GPU峰值41897/47118 MiB。其GPU-util均值60.63%/61.01%，原配置61.93%/62.12%；利用率没有提高，但单位时间处理的动作更多。该方案不是最终默认值；汇总为 `final_comparison.json`，原始目录 `final_baseline/`、`final_optimized/`。

重算12环境的18步试验峰值降至23761/26390 MiB，证明它能显著恢复显存余量，代价是少量重算耗时。最终以上方新的50步复测为准，单项加速不相加。

## 正确性及稳定性验证

- 相关CPU回归覆盖视觉编码器、视觉投影、模型检查点、并行教师查询、在线性能流程和RxR配置。最终回归79 passed、2 skipped，退出0，日志 `final_regression.log`。
- 真实导航网络的前向输出、所有参数梯度、输入梯度及随机数状态，在开启/关闭导航重算时逐位一致：1 passed，退出0；日志 `recompute_test.log`。
- 真实GPU检查DINO是否保留中间层输出：最终token逐位一致，1 passed、退出0；日志 `lean_parity.log`。
- 编译数值审计使用两卡各前三个真实全景批量：导航消费的CLS相对差约0.15%—0.17%，深度约0.11%，均通过0.2%相对误差检查。编译不是逐位等价。最初对随机输入全部token的检查约0.30%，导航实际不消费的patch也被包含；后续改为验证真实导航输入及实际消费的CLS，检查线没有放宽。不能把该验证扩展为世界模型patch路径的结论。
- 12环境场景资源压力测试：每次新episode切换场景，两卡各覆盖全部59个训练场景，完成12次更新，无OOM，全部有效更新及冻结参数检查通过，GPU峰值43176/43398 MiB。这一轮尚未开启导航重算；场景重载时间不计入吞吐提升结论。证据 `scene_stress/`。
- 真实双卡训练均检查冻结视觉参数哈希不变、残差MLP真实更新、损失全部有限，结果在各rank JSON的 `audit` 字段中。
