# Research Dossier：英文机器人/具身智能 IEEE 期刊场景分析

> 场景：英文机器人与具身智能期刊；具体期刊尚未确定；当前仅采用通用 IEEE 期刊结构。  
> 分析日期：2026-08-28。  
> 证据边界：本文档只分析投稿场景、评审关注点、常见成稿结构和本项目约束，不判断技术路线相对最新工作的缺口，也不把网页示例、README 声明或图片中的数值当作当前稿件已经复现的实验结果。

## 场景定位与结论

从项目 README、总体框架图和工程差异说明看，本稿属于机器人学习与具身智能交叉方向，任务核心是连续环境中的视觉语言导航（VLN-CE）：智能体根据自然语言，在连续三维环境中构建或利用拓扑图并完成闭环导航。现有材料形成了“联合预训练—在线监督微调—在线强化微调”的方法主线，实验对象覆盖 R2R-CE 与 RxR-CE。[L1][L3][L4] 这与 IEEE Robotics and Automation Society（IEEE 机器人与自动化学会，简称 RAS）期刊的机器人算法、系统集成和应用实验范围有自然交集；但在没有选定期刊之前，不能承诺某一本期刊的页数、审稿匿名方式、开放获取费用、补充材料上限或格式细节。

目前最稳妥的写作基线是：先按完整 IEEE journal article 组织中文逻辑母稿，保留能支持长篇期刊论证的方法细节、实验协议、消融、误差分析与局限性；目标期刊确定后，再在“完整 Transactions 论文”与“精炼 Letters 论文”之间裁剪。IEEE Transactions on Robotics（T-RO）的官方定位强调对机器人领域现有水平的“major advances”，并接受理论、设计、实验、分析、算法、系统集成和应用案例的组合；IEEE Robotics and Automation Letters（RA-L）则强调及时、简洁地报告创新研究和应用结果，官方页面当前给出的长度为 6 页、最多另加 2 页且需付费。[O5][O6] 这两个刊物只是用于说明选刊分叉，不代表已经替用户选刊。

## Venue Requirements

### 已核验的 IEEE 通用要求

1. **文章组成。** IEEE Author Center 给出的典型期刊论文要素包括题目、作者、摘要、关键词、首页脚注、引言、方法、公式、结果、讨论、结论、参考文献和致谢。引言需要回顾相关研究、说明研究问题及其重要性；方法应详细到可复现；结果用图表呈现发现；讨论解释结果为何构成贡献；结论应说明影响与后续工作且不得夸大。[O1]
2. **题目、摘要和关键词。** 题目应具体、简洁、具有描述性，避免用“new”“novel”自我宣告。摘要应为一个段落、最多 250 词，自包含，不使用缩写、脚注、参考文献或数学公式，说明研究、结论和潜在影响，并突出新意；同时提供 3–5 个关键词或短语。具体期刊若另有更严格要求，以期刊页面为准。[O1]
3. **模板。** 当前可以用通用 IEEE 双栏期刊结构搭建逻辑，但正式投稿前必须从 IEEE Author Center/目标期刊入口取得对应模板，不应把某个会议模板或 RA-L 的页数规则默认套到所有 Transactions 期刊。[O1]
4. **同行评审。** IEEE 通用政策要求一篇文章在被接收前至少由两名合格、独立的评审人评价。多数 IEEE 出版物使用单匿名评审，但也存在双匿名和透明评审；具体采用哪一种必须以目标期刊为准。[O2]
5. **原创性与独家投稿。** 投稿内容应为作者原创，不得同时投往其他出版物；所有引用、复述、数据、图和表都应正确标注来源。不得捏造或篡改数据，也不得通过图像处理改变科学含义。[O3]
6. **会议扩展稿。** 如果新稿建立在作者先前会议论文上，IEEE 允许形成更完整的期刊稿，但要求期刊稿包含实质性更多的技术信息，引用会议版本，并明确两者差异。[O3] 本项目 README 指向 arXiv:2512.20940，因此投稿前还需核对目标期刊的预印本政策，并在封面信或系统中如实披露相关版本；本分析不把预印本等同于会议论文，也不替目标期刊判断其合规性。[L1]
7. **补充材料。** IEEE Author Center 说明补充材料应明确标为 supplementary，并在投稿时作为独立文件上传；图形摘要也要和正文一起接受同行评审。数据集或可执行材料建议附 README，说明内容、大小、平台、环境、组件、安装、运行、预期输出和联系方式。[O4]
8. **生成式 AI 使用。** IEEE RAS 官方指南援引 IEEE PSPB Operations Manual：论文中由 AI 生成的文字、图、图像或代码应在致谢中披露，注明所用系统、涉及的具体章节及使用程度；仅做编辑和语法增强通常不属于该条的核心情形，但官方仍建议披露。作者始终对内容、引用、科研诚信与最终表述负责。[O7] 本稿由 PaperSpine/Codex 辅助组织，后续必须保存实际使用边界，并在投稿时按最终目标期刊规则决定准确披露文本。

## Review Criteria

IEEE Author Center 明确列出编辑和评审人的七个关注维度：范围匹配、原创性、有效性、数据、清晰性、合规性和领域推进程度。[O2] 对本稿应转化为以下可回答的问题：

| IEEE 评审维度 | 本稿需要给出的答案 | 容易触发的质疑 |
|---|---|---|
| Scope（范围） | 工作为何是机器人导航、闭环决策或具身智能问题，而不只是视觉/语言模型换骨干 | 摘要只谈模型指标，未解释机器人决策意义 |
| Novelty（原创性） | 相对作者自己的 ETP-R1/arXiv 版本，新稿新增了什么方法、证据或分析 | 沿用旧标题、旧框架和旧结果，却没有清楚的版本差异 |
| Validity（有效性） | 训练阶段、对照组、数据划分、指标、超参数和评测过程是否能检验论文主张 | 只报告最优 checkpoint；基线训练预算或输入特征不公平；缺少方差或失败分析 |
| Data（数据） | R2R-CE、RxR-CE 结果是否使用正确 split 和标准指标；Gemini 增强数据如何生成、过滤和防止污染/泄漏 | README 或图片数值未经新实验日志核验便写入正文；数据来源和筛选过程不透明 |
| Clarity（清晰性） | 问题、方法、训练流程与实验验证是否一一对应；符号和缩写是否先解释 | 将预训练、SFT、RFT、RAE/DINOv2、世界模型等模块堆叠成名词列表，没有说明各自解决的问题 |
| Compliance（合规性） | 引用、匿名、AI 披露、已有版本、数据许可和补充材料是否符合目标期刊政策 | GitHub/arXiv/实验室外链泄露身份；未披露 AI 生成内容或已有版本 |
| Advancement（推进程度） | 哪个可推广的机器人学习认识由成套实验支持，而不是只有榜单提升 | 贡献被写成若干工程改动；没有跨 R2R/RxR 或跨训练阶段的一致证据 |

就期刊场景而言，编辑首先会看“适配与贡献是否值得送审”，评审人才会深入看实现和数值。因此摘要、引言末尾的贡献列表、总体框架图和结果总表必须讲同一件事。对于 T-RO 类型的完整 Transactions 稿，官方 scope 对“major advances”的要求意味着仅有有限配置改进通常不足，需要方法、系统或实验证据达到更强的整体推进；对于 RA-L 类型的 Letters 稿，重点则是及时、简洁的创新结果，篇幅会迫使作者缩短背景和实现细节，并把复现信息移入补充材料。[O5][O6]

## Accepted Paper Patterns

### 证据说明

本地 `source_index.md` 只索引了项目说明、设计/运维文档和两张图片，没有收录目标期刊已接收论文样本；具体期刊又尚未确定。[L2] 因此本节不是“统计了已接收论文之后得到的录用规律”，而是依据 IEEE 官方文章结构、官方评审标准、T-RO/RA-L scope 与本项目材料形成的**建议性结构模式**。不能把这些模式表述为录用保证。

### 推荐结构模式

1. **题目和摘要先给机器人问题、关键机制与验证范围。** 题目避免“novel/new”，优先出现可检索的任务和方法实体，例如 continuous-environment vision-language navigation、topological planning、reinforcement fine-tuning。摘要按“问题—方法—实验范围—主要结论—意义”闭环；具体数值未核验前不写。[O1]
2. **引言形成单一主线，而不是模块清单。** 先说明连续环境 VLN 中拓扑规划的价值及其训练瓶颈，再提出本文要回答的问题；随后解释为何联合预训练、在线 SFT 与在线 RFT 构成连贯解法，最后用可验证的贡献条目收束。README 和 Overview 图已经提供三阶段骨架，但新稿必须根据实际版本重画并核验，不能直接把现有宣传性文字当结论。[L1][L3]
3. **相关工作按问题关系组织。** 建议围绕“连续环境 VLN 与拓扑规划”“数据规模化与多任务预训练”“模仿学习与闭环强化微调”组织，而不是逐篇罗列。这里仅给组织轴，不判断哪一项构成 SOTA 缺口。
4. **方法部分把训练管线和可复现细节分层。** 先给问题定义与统一符号，再给系统总体图，然后分别说明模型骨架、联合预训练、在线 SFT、在线 RFT；最后列出训练和推理算法、奖励、关键超参数与资源。项目差异文档表明 ETP-R1 沿用 ETPNav 的导航骨架并扩展训练范式、数据和任务编码，这种“保留什么—新增什么—如何交互”的写法比按代码文件讲解更适合期刊。[L4]
5. **实验按研究问题组织，而不是按脚本目录组织。** 至少应回答：整体方法是否有效；每个训练阶段带来什么；R2R 与 RxR 是否呈现一致趋势；关键设计是否必要；提升是否以路径效率、稳定性或计算开销为代价；失败发生在哪里。R2R SFT、R2R GRPO、RxR SFT、RxR GRPO 四个计划实验单元应形成同一证据矩阵，而不是四张彼此孤立的表。[L0]
6. **结果与讨论分工明确。** 结果部分报告事实和统计，讨论部分解释跨任务差异、闭环训练行为、限制、数据偏差和可迁移意义。IEEE 官方结构明确把 Results 与 Discussion 分开，并要求结论不夸大。[O1]
7. **图表承担信息压缩。** 一张系统总图展示三阶段数据流；一张主结果表覆盖标准 split/指标；阶段消融和关键机制消融分别成表；训练稳定性、样例轨迹或失败类型适合成图。表中必须标注指标方向、split、是否使用额外数据以及结果来源。当前 `assets/result.png` 可以帮助理解预期表格布局，但不能在未核验时作为新稿数据源。[L3]
8. **复现材料与正文互相指向。** 正文给足以判断有效性的关键设置，详细环境、数据准备、命令、checkpoint 选择规则和额外可视化放补充材料，并提供 IEEE 建议的 README 信息。[O4] 工程中的设计与运维文档可以转化为复现说明，但内部机器地址、个人路径、容器名和受保护资源信息不得进入公开论文或补充材料。[L5]

## Constraints for This Paper

### 内容与证据硬约束

1. **语言流程存在明确的两阶段要求。** 配置中的 `output_language` 当前为 `zh`，而目标场景是英文期刊；特殊要求又明确“先形成中文逻辑母稿，实验结果回填并确认后再形成英文定稿”。因此当前中文写作是逻辑中间件，不是可直接投稿的最终稿。目标期刊确定且结果确认后，应再形成完整英文版并按对应模板排版。[L0]
2. **未完成实验一律保留 `[待填]`。** 可以预先设计论证位置、表结构和判断标准，但不得填入估计值、README 值、图片值、旧 checkpoint 值或“合理看起来”的数字。[L0] 即使旧 `assets/result.png` 展示了完整表格，仍须由本轮实际实验记录逐项回填。[L3]
3. **本地宣传性主张必须重新验证。** README 使用“first application”“state-of-the-art”等强表述，并给出旧论文身份；这些只能当作待核验主张，不能因为出现在代码仓库中就自动继承到新稿。每个最强、首次、显著提升或跨任务泛化主张都必须有当前文献与实验依据。[L1]
4. **区分方法事实、设计计划与实验事实。** `docs/` 中既有已实现设计，也有核验记录和后续实验方案；例如原生 CLS RAE-NWM 文档明确限定其当时范围为 R2R SFT/评测、不含 GRPO 与 RxR，并且验收不要求性能提升。[L5] 这类工程设计可支持方法描述或局限性，但在完整训练/评测完成前不能写成性能贡献。
5. **四类核心实验必须保持可比性。** 配置计划覆盖 R2R SFT、R2R GRPO、RxR SFT、RxR GRPO。[L0] 对应结果应统一记录数据 split、随机种子、训练预算、选点规则、评测脚本版本和指标定义；若某一任务采用不同视觉编码器、额外数据或训练步数，须在表中显式说明。
6. **数据增强必须有可审计的来源说明。** README 表明预训练数据涉及 Gemini API 生成指令以及 R2R、RxR、Prevalent、Marky 等来源。[L1][L3] 期刊稿需说明模型/接口版本、提示与采样过程、过滤标准、幻觉控制、质量抽检、许可与可能的数据污染；缺失信息应标为待补证，不得逆向猜测。
7. **复现性不能只依赖 GitHub 链接。** 方法、实验和补充材料应记录实际软件版本、关键超参数、训练硬件类别、checkpoint 选择和评测命令；项目内部的绝对路径、SSH 别名、账号和机器身份属于运维信息，不进入公开稿件。
8. **已有版本与匿名要求可能冲突。** README 已公开论文题目、作者身份线索和 arXiv 链接。[L1] 如果最终投 RAS 全资期刊，送审 PDF、附录、补充材料、文件元数据和代码链接必须按双匿名规则清理；已有 arXiv 可以存在，但正文不能主动用外链或措辞暴露身份。[O8]
9. **AI 辅助写作必须留痕。** 本轮中文母稿由 Codex/PaperSpine 辅助构建。作者需逐句核对事实和引用，记录 AI 参与了哪些章节和何种程度；如果最终形成了 AI 生成内容，应按 IEEE/RAS 与目标期刊的最新政策准确披露，AI 不能作为作者。[O7]
10. **强主张的边界必须提前锁定。** 在所有计划实验完成、独立复核和文献核验之前，标题、摘要和结论不得使用 “first”“state-of-the-art”“general”“robust” 或 “significant” 等无条件表达。当前可以写“我们研究/提出/评估”，不能写“我们证明/建立新的最佳结果”。

### 投稿前的场景决策闸门

- **先选文章类型，再冻结篇幅。** 如果证据支持机器人领域的整体重大推进且需要完整机制、消融和讨论，可评估 T-RO 类 Transactions；如果贡献单一、结果成熟且需要快速简洁表达，可评估 RA-L 类 Letters。[O5][O6]
- **先核验结果，再写英文摘要。** 主结果、消融、稳定性和失败分析全部完成后，才能替换 `[待填]` 并形成投稿摘要。
- **先做版本差异表，再提交。** 对 arXiv/旧 ETP-R1 与新稿逐项列出方法、数据、实验和结论差异，供作者和编辑判断原创增量。
- **先做匿名与伦理检查，再生成提交包。** 检查作者信息、致谢、基金、图中标识、PDF 元数据、外链、AI 披露和数据许可；具体顺序以目标期刊的送审/终稿规则为准。
