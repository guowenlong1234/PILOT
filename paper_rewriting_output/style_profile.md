# 写作风格规范

## 1. 总体定位

当前产物是面向英文机器人/具身智能期刊的中文逻辑母稿。中文阶段优先保证论证、证据与术语稳定，不追求逐句对应英文；英文定稿阶段再按目标期刊模板压缩篇幅和调整句法。文章采用完整期刊论文的解释深度：不仅报告是否提升，还回答为什么有效、在什么条件下有效、代价是什么、何时失败。

核心组织单位不是模块数量，而是一条可审查的贡献承诺。引言、方法、实验和讨论必须围绕同一问题展开：冻结的表征世界模型能否在不查询未来模拟器观测的情况下，为在线拓扑候选提供有用的未来视觉证据，并与监督/强化微调形成可复现的闭环训练体系。

## 2. 结构与段落节奏

### 标题与摘要

- 标题先写任务与关键机制，避免 `new`、`novel`、`first`、`state-of-the-art` 等未经证据支持的自我评价。
- 中文摘要按五句功能组织：问题与重要性；具体缺口；本文贡献；验证证据；受边界约束的意义。
- 实验未完成时，摘要中的具体结果使用 `[待填]`，不使用估计值，也不以“预计超过”代替结果。

### 引言

引言使用“问题—已有进展—具体缺口—研究问题—贡献承诺—证据预告—读者收益”的阶梯。每段只完成一个动作。先承认 ETPNav/ETP-R1 等拓扑方法的结构优势，再指出当前缺少的是可验证的未来表征对齐与闭环决策证据，而不是泛称图式方法不会推理。末尾贡献列表控制在三项，每项分别落到方法、训练/系统契约和实验证据。

### 相关工作

按问题轴综合文献：连续环境 VLN 与拓扑规划；视觉表征与世界模型前瞻；在线监督学习与强化微调。每一小节结尾都要说明现有工作已经解决什么、仍留下什么、本工作在哪一条窄边界上回应。避免“一篇论文一句话”的作者名单式综述。

### 方法

先定义任务、图状态、候选 ghost 和动作空间，再给总体数据流。后续沿信息流分解：DINOv2/RAE 表征；历史上下文与原生 CLS+patch NWM；q0→CWP→q1 未来候选；Top-5 CLS adapter 与 E24 有界重排；基础/调整后监督损失；冻结式 GRPO。每个模块先写它解决的具体挑战，再写输入输出与设计理由，最后写梯度/冻结边界。

### 实验与讨论

实验按研究问题组织，不按脚本或数据目录组织。每个结果小节遵循“问题—证据—比较—解释—边界”。主表分开报告 R2R-CE 与 RxR-CE，表中显式标注 split、控制器、额外数据、随机种子、checkpoint 选择规则和指标方向。讨论重点解释未来预测质量、有效候选覆盖、动作翻转以及成功/失败之间的关系，不重复抄写表格数字。

## 3. 论断强度

- 代码、shape、严格加载、数值一致性和冻结检查支持“实现正确/接口一致”，不支持“导航有效”。
- 单个完整 split 的结果支持“在该设置下观察到”，不自动支持“稳定”“普适”或“显著”。
- 三随机种子或适当统计分析完成后，才讨论稳定性；若只有 episode bootstrap，明确它不能替代训练种子方差。
- 未完成实验使用“我们将检验”“该实验用于回答”，不要使用“结果表明”。
- 当前中间结果未超过基座，正文必须如实保留这一边界；若后续最终结果改变，再同步修改摘要、贡献、结果和结论，不能只替换表格。
- NavMorph 已覆盖宽泛的 VLN-CE 世界模型，NavGRPO 已覆盖宽泛的 VLN GRPO。新颖性必须限定到原生 CLS+patch、在线拓扑 ghost/E24 对齐、冻结模块契约和连续环境闭环验证的组合。

## 4. 术语规范

首次出现术语时先给中文解释，再给英文全称与缩写。后续固定用法：

| 中文术语 | 英文定稿术语 | 使用说明 |
|---|---|---|
| 连续环境视觉语言导航 | Vision-Language Navigation in Continuous Environments (VLN-CE) | 任务总称 |
| 图式/拓扑导航策略 | graph-based/topological navigation policy | 强调在线拓扑图，不与一般地图方法混用 |
| 监督微调 | supervised fine-tuning (SFT) | 当前 DAgger 在线监督阶段 |
| 强化微调 | reinforcement fine-tuning (RFT) | 泛称；具体算法处写 GRPO |
| 组相对策略优化 | Group Relative Policy Optimization (GRPO) | 首次解释组内相对优势与 KL 约束 |
| 表征自动编码器 | representation autoencoder (RAE) | 说明其作用是提供语义潜在空间 |
| 世界模型 | neural world model (NWM) | 说明其预测未来表征而非直接渲染 RGB |
| 原生 CLS+patch 序列 | native CLS-plus-patch token sequence | 固定为 1 个 CLS 与 256 个 patch token |
| 候选幽灵节点 | candidate ghost node | 首次解释为未访问但可执行的拓扑候选 |
| 主动前视 | active lookahead | 指不查询未来模拟器观测的预测式候选重排 |

不把 RFT、RL、GRPO 交替当作同义词；不把预测潜变量称为“真实未来图像”；不把 agreement 称为概率置信度。

## 5. 语言与句法

- 中文句子优先采用清楚的主谓结构，减少连续名词堆叠。一个句子只保留一条主要因果关系。
- 段首先指出本段功能，段尾给出与下一段的逻辑接口。
- 贡献句使用“提出—构建—验证”的动词梯度；结果句使用“观察到—支持—但不证明”的证据梯度。
- 避免宣传性形容词，如“强大”“卓越”“革命性”。用可核验事实替代评价。
- 英文定稿避免长串缩写开篇、悬空的 `This`、过度使用被动语态和模板化的 `It is worth noting that`。
- 数值报告同时给比较对象、数据划分和指标；百分点变化与相对百分比变化不得混用。

## 6. 引用与图表

- 所有外部事实使用真实 `\cite{key}`，不得手写 `[1]`。
- 优先引用原始论文、官方出版页或官方 arXiv 元数据；综述用于分类，不替代核心算法原始来源。
- 旧 `assets/Overview.png` 只能作为原版 ETP-R1 背景图，新的期刊稿需要重画包含 RAE/NWM/E24/冻结式 GRPO 的方法图。
- `assets/result.png` 是旧发布结果布局参考；新结果必须从原始 JSON 回填并显式区分旧 ETP-R1 与当前扩展。
- 图注应能脱离正文说明输入、模块、训练/冻结状态和箭头含义；表注应解释加粗、下划线、指标方向与统计方式。

## 7. 占位符与修订协议

统一使用 `[待填：对象/指标/来源]`，例如 `[待填：R2R val_unseen 三种子 SR 均值±标准差]`。不得用 `TBD` 隐去应补内容。回填结果时同步检查四处：摘要、引言贡献、结果小节、结论。若结果没有达到预期，不删除负结果，而是收缩贡献并把机制发现或边界分析提升为主要价值。
