# Methods & Reproducibility Review

## Summary

本稿的方法动机清楚：用冻结的原生 CLS+patch 世界模型为在线拓扑 ghost 提供候选相关未来证据，再用 Top-5 有界残差限制预测误差的影响，并把前视模块限定为“在 SFT 中学习、在 GRPO 中冻结”。这种收缩后的技术主张与 `confirmed_contribution.md` 的边界基本一致，也没有把尚未得到的性能提升写成既成事实。

但以方法正确性和可复现性标准衡量，当前版本仍不具备投稿条件。最严重的问题不是数值尚未回填本身，而是冻结式 GRPO 的核心等价性尚未被方法定义保证：冻结模块参数不等于冻结其输出；只要 E24 残差仍依赖会更新的导航特征、base logits 或动态 Top-K，current、old、reference 三个分布就未必叠加“同一残差”。此外，一步 q0/q1 链路与尚未实现的二、三步实验在方法段中部分混写；oracle q1、无 q1、h=1/2/3 的训练和评测协议也未定义到可执行程度。实验方面，主表混放已知可能存在 controller/teleport 口径差异的旧结果与现代基座，逐级消融还不能证明每行只改变一个变量，最近的世界模型导航基线及参数匹配控制也缺失。

综合判断：**需要大修；在下列 CRITICAL 项关闭前，不能把该稿称为技术上验证完毕或可复现的完整论文。**

## Strengths

1. **主张边界较诚实。** 摘要、主结果段和结论明确保留占位符，并说明早期 checkpoint 尚未稳定超过 RAE/DINOv2 基座（摘要；“主结果与阶段递进”；结论）。这与 `evidence_bank.md` 中 E04/E11--E16 的证据等级一致。

2. **一步与多步的研究目的设计合理。** 稿件把 h=1 定为主设置，把 h=2/3 定位为收益、误差和开销的机制分析，而非预设“越远越好”（“问题定义”“q1 来源与预测视野长度”“讨论”）。这一方向与 `results_validation.md` 的解释边界一致。

3. **安全边界是可检验的，而非泛泛口号。** Top-5、残差上界、STOP/非 Top-K logit 不直接改写、无效行回退、世界模型与 CWP 冻结等约束都能转化为单元测试或运行时统计（“总体框架”“CLS 适配与 E24 有界重排”）。`evidence_bank.md` 的 E05--E09 已为其中一部分提供实现和数值一致性证据。

4. **稿件主动承认工程正确性不等于导航收益。** “原生 CLS+patch 表征世界模型”和“CLS 适配与 E24 有界重排”明确指出 parity、限幅或回退不能证明导航性能提升。这一点方法论上正确。

5. **机制实验覆盖了主要失败模式。** oracle--predicted 差距、动作翻转的修正/伤害、future-valid、预测误差、Top-K、上下文长度及延迟，能直接回应 `confirmed_contribution.md` 中的新颖性和意义风险。

## CRITICAL

### C1. 冻结式 GRPO 的“同一残差”结论没有被当前定义保证

- **位置：**“冻结式 GRPO”（正文第 135--137 行）；同时影响引言第 41 行和贡献第 46 行。
- **问题：** 稿件声称 current、old、reference distribution 都叠加同一冻结残差，因此概率比只反映基础策略变化。但“冻结世界模型、adapter 和 E24 的参数”只保证这些参数不更新，并不保证残差数值不变。E24 还读取“候选所有者表示、语言表示、导航上下文和基础 Top-K”；如果其中任一输入来自正在更新的基础策略，或者 Top-K 由各自的 base logits 动态选出，则三条分布的 residual vector、action mask、甚至被修改的候选集合都可能不同。此时概率比和 KL 同时混入了前视输入变化及离散 Top-K 切换，当前归因结论不成立。
- **可执行修复：** 明确采用一种实现契约并写进算法：
  1. 在 rollout 时用固定的 SFT 快照产生候选集合、Top-K、导航/语言特征和残差，并缓存每个状态的完整 action-aligned residual vector 与 mask；current、old、reference 的 log-prob 重算都读取同一缓存；或
  2. 冻结所有会进入 residual 的上游特征提取器，并固定 Top-K 来源，使三分布的残差函数输入完全相同。
  同时列出 GRPO 唯一可训练参数组。新增自动测试：对同一 batch 分别构建 current/old/reference 后，逐元素断言 residual、Top-K index、valid mask 完全一致（浮点量给定容差），并验证把 residual 置零后概率比退化为基础 GRPO。若实际实现不是上述语义，应删除“概率比只反映基础策略变化”，重新定义并论证目标。

### C2. 已实现的一步链路与计划中的二、三步变体仍然混写

- **位置：**“候选相关 q0、CWP 与 q1”第 103--105 行；“预测质量、候选覆盖与计算开销”第 268 行；“限制”第 286 行。
- **问题：** E06 只支持 q0/CWP/q1 一步链路，E13 明确把 h=2/3 列为 E5 计划实验；限制段也说多步变体“尚需正式实现”。但方法段用现在时声称实验变体递归构造 $\widehat X_{t+2}$、$\widehat X_{t+3}$，后文还直接列出 q2/q3 分项耗时。读者无法判断多步算法是已经实现、仅设计完成，还是只是一项未来工作。
- **可执行修复：** 当前草稿把 h=2/3 统一标成“预注册/计划中的受控扩展”，不用现在时描述已经运行；只有在代码、测试、日志和原始评测 JSON 齐备后，才改写为完成时事实。为 h=2/3 单独给出伪代码、状态递推式、CWP 条件更新、停止/无效槽规则、每步噪声与随机种子规则，并记录实现提交号。最终回填前执行逐视野 smoke test、全 split 测试和结果 manifest 校验；若未完成，就从摘要的结果承诺、贡献条目和最终结论中删除多步“验证”措辞，只保留为未来工作。

### C3. 主结果表当前不满足公平比较条件

- **位置：**“数据集与指标”第 143--145 行；主表第 178--199 行；`figure_asset_map.md` 的 T1 使用约束。
- **问题：** 正文已承认现代链路与旧发布结果存在 teleport/control 口径风险，但同一主表仍把旧 ETP-R1、现代 RAE/DINOv2 基座和新方法放在相邻行，且没有 split、controller、语言、reported/rerun 或训练预算列。R2R 表中还混入 nDTW/SDTW 空缺，RxR 行没有明确语言设置。这样的排版会自然诱导直接比较，违反正文自己的公平性声明，也无法确认旧结果、现代基座和新方法是否来自同一评测协议。
- **可执行修复：** 在结果 manifest 中为每行固定 `dataset/split/language/controller/sensor/success_threshold/max_steps/checkpoint/selection_rule/seed/source_json`。主表只保留严格同协议重跑的行；无法重跑的 published numbers 放入独立面板，显式标“仅供背景、不可直接求差”，并给引用。至少补充 split 与 controller 列。按 `figure_asset_map.md` 的 T1 计划加入 ETPNav；最近的世界模型导航方法（如稿件已讨论的 NavMorph）若协议不兼容，也应在独立的已发表结果面板或定性功能对比表中公平说明，而不是静默缺席。

### C4. 核心经验主张仍全部依赖占位符，摘要和结论尚不可定稿

- **位置：**摘要第 26 行；实现表第 163--165 行；主表、逐级消融表、horizon 表、动作翻转表及两张图占位；结论第 290 行。
- **问题：** `evidence_bank.md` 明确说明当前完整方法、主动前视 GRPO、RxR、多步、oracle、消融、翻转因果分组和多种子实验尚缺失。现有 E05--E10 只能支持系统契约和一步诊断，不能支持性能贡献。当前摘要把一整个结果句作为单一自由文本占位，其他单元格多为无来源的 `[待填]`，没有形成可审计的回填契约。
- **可执行修复：** 为每个占位符建立具名键并绑定结果 manifest，例如 `T1.R2R.val_unseen.RWM_SFT.SR.mean`，同时记录原始 JSON、配置、checkpoint 哈希、代码提交、种子、episode 数和选择规则。表格回填脚本应在 split/episode 数/指标字段缺失时失败。所有主实验至少完成预先声明的种子或明确降级为单次运行并禁止稳定性/显著性措辞。摘要只能在 T1--T5 和不确定性完成后生成最终数值句；正文中的方框图、文本占位和 `[待填]` 必须是投稿硬阻断项。

### C5. oracle q1 不是可执行、无泄漏的实验定义

- **位置：**“q1 来源与预测视野长度”第 222--244 行；horizon 表 oracle 行；`results_validation.md` 第 7 行。
- **问题：** “真实未来上界”没有说明每个 ghost 的真实未来表征如何取得。实际 rollout 只观察被执行分支；若要为 Top-5 每个候选提供 oracle token，就需要可复位的分支模拟、精确位姿和传感器渲染。若只用实际采取动作后的下一帧，则未采取候选没有 oracle，且会产生选择偏差。horizon 表把 oracle 的 CLS 误差写死为 0，也未说明误差是在 adapter 前还是后计算。训练时用 oracle、仅评测时替换、还是固定同一个 E24 checkpoint，会产生完全不同的解释。
- **可执行修复：** 单独写 oracle 协议：候选位姿如何从 ghost 转为模拟器状态、是否克隆/恢复 simulator state、渲染哪些传感器、碰撞/不可达候选如何处理、oracle token 的编码/归一化、是否只离线使用、训练与评测分别使用哪种 q1。为所有候选使用同一分支规则并报告 oracle coverage。把“误差为 0”限定为“adapter 前、同一编码器和预处理下按定义复制的目标 token”；否则照实计算。若无法获得无偏的候选级真实未来，就把该行改名为“executed-branch diagnostic”，不得称 oracle 上界。

## MAJOR

### M1. q0、q1 与预测视野 h 的时间语义不清，公式和文字无法一一对应

- **位置：**“问题定义”第 74--79 行；“候选相关 q0、CWP 与 q1”第 101--105 行。
- **问题：** 公式直接把 $W(H_t,c_t^i)$ 记成 $\widehat X_{t+1}^i$，而文字又描述先预测 q0、再由 CWP 从 q0 产生 q1 条件、再预测 q1。当前无法判断 q0 是候选到达后的第一未来状态、用于生成 q1 的中间状态，还是“第 0 个未来槽”；也无法确认 h=1 对应 q0 还是 q1。这会影响预测误差对齐、oracle 定义和延迟计数。
- **可执行修复：** 增加一张索引表或三条方程，明确决策时刻、候选物理位姿、q0/q1 的目标时间/位置、CWP 输出和 h 的对应关系。方法、图 F1/F2、表 T3、日志字段统一使用同一编号；给一个单候选的时序示例作为复现检查。

### M2. 联合 SFT 的梯度边界只写了结论，没有写出使结论成立的计算图

- **位置：**“联合监督训练”第 125--133 行。
- **问题：** $\mathcal L_{\mathrm{adj}}$ 基于调整后的完整 logits；若 base logits 或导航/语言特征没有显式 detach，它会反向更新基础策略，和“调整后损失只更新 adapter 与 E24”冲突。正文虽提到 CPU replay 保存 detached future token、语言和基础 logits，但未说明候选 owner 特征、几何特征、mask 是否也停梯度，也未说明基础优化与 replay 优化的先后关系。若基础参数先更新，缓存 logits/特征会成为 stale data。半精度 replay 还可能改变训练数值。
- **可执行修复：** 给出参数更新矩阵和 SFT 单步伪代码，列出每个张量的 `requires_grad/detach` 状态、两个 optimizer 的 step 顺序、replay 生命周期/容量、微批大小、loss 归一化和梯度累积。报告 $\lambda_{adj}$、两个损失各自的学习率/调度/权重衰减/裁剪。新增梯度测试覆盖所有命名参数，并做 live-compute 与 fp16 replay 的 loss/logit 差异检查。

### M3. “STOP 隔离”表述强于实际保证

- **位置：**贡献第 45 行；“CLS 适配与 E24 有界重排”第 115--123 行；讨论第 280 行。
- **问题：** 公式只保证 STOP logit 数值不直接改变。只要 Top-K MOVE logits 改变，STOP 的 softmax 概率、排名和最终动作仍可改变。因此“停止动作隔离”容易被理解为 STOP 决策不受前视影响。逐候选 $|\delta_i|\leq\delta_{max}$ 也不自动给出整体分布或性能安全保证。
- **可执行修复：** 全文统一改成“STOP logit 不直接加残差”，避免“STOP 动作隔离”。给出精确 $\delta_{max}$ 和残差参数化（如 tanh）；如果声称概率扰动受限，给出相应 log-odds/KL 上界或仅保留经验描述。动作分析中单列 STOP$\rightarrow$MOVE 与 MOVE$\rightarrow$STOP 翻转。

### M4. adapter、E24、CWP 与候选条件缺少最低限度的算法定义

- **位置：**“总体框架”“候选相关 q0、CWP 与 q1”“CLS 适配与 E24 有界重排”。
- **问题：** 目前没有 adapter/E24 的层数、隐藏维度、激活、归一化、参数量、几何编码、语言/owner 表示来源、token 聚合方式，也没有 CWP checkpoint、输出参数化、候选有效阈值和坐标系。仅靠模块名无法独立实现。
- **可执行修复：** 新增结构表和推理伪代码；逐项给出输入 shape、坐标系/单位、网络层、参数量、初始化、残差上界、mask 和 tie-breaking。标明 DINOv2、RAE-NWM、DINO-CWP、waypoint predictor 的公开模型 ID/版本、checkpoint SHA-256、预处理、归一化统计、采样器配置与随机噪声策略。

### M5. 回退与冷启动策略没有定义到候选级，可能引入系统性选择偏差

- **位置：**“总体框架”第 83 行；“原生 CLS+patch 表征世界模型”第 99 行。
- **问题：** “逐行回退”不清楚是整个环境行回退，还是仅失败候选置零残差；当部分 Top-5 失败时如何处理、是否重排剩余候选、padding/不可达/STOP mask 的顺序均未说明。四帧不足即关闭前视也会让前视只在 episode 后段生效，当前 future-valid 和 flip rate 可能受此强烈影响。
- **可执行修复：** 给出候选级状态机：history 不足、q0 失败、CWP none、q1 非有限、部分 future slot 无效及全行无效分别如何处理。报告按失败原因、决策步和 episode 阶段分层的 coverage/fallback rate；Top-K/context 消融保持相同可比较样本或同时报告样本变化。

### M6. 逐级消融并非天然的单变量对照，关键参数匹配控制缺失

- **位置：**“逐级模块消融”第 201--220 行。
- **问题：** Base、+RAE/DINOv2、+RGB-NWM、+E24、+GRPO 没有操作性定义。“固定同一预训练基座和 SFT 起点”与“增加 RAE/DINOv2 后架构和参数变化”可能不能同时成立；GRPO 行又同时改变训练目标和训练预算。现有表无法分辨未来信息、额外参数、额外训练或计算量的贡献。
- **可执行修复：** 为每行列出唯一变化、初始化 checkpoint、可训练参数、训练步数/样本量和推理计算。至少增加：zero-delta、E24 但无未来/打乱未来、q0-only（或清楚定义的 no-q1）、predicted q1，以及参数量相近但不读取 NWM future 的控制。GRPO 增益应与“相同 SFT checkpoint + 相同 RL 预算、但 zero/no lookahead residual”的 GRPO 对照比较，而不是只与 SFT 行比较。

### M7. no q1、oracle q1、predicted q1 的训练条件和模型复用规则未定义

- **位置：**“研究问题与对照”第 170--172 行；“q1 来源与预测视野长度”第 222--242 行。
- **问题：** “无 q1”可能表示不运行 NWM、输入零 token、只用 q0、令 residual 为零，四种语义不同。也不清楚每种来源单独训练 adapter/E24，还是固定同一 checkpoint 仅在评测替换输入；后者有分布偏移，前者又引入训练随机性和预算差异。h=2/3 是分别训练、共享 h=1 头还是聚合多个未来状态，也未说明。
- **可执行修复：** 建立 variant matrix，逐行定义训练输入、评测输入、是否运行 q0/q1、adapter/E24 是否重训、参数量、训练预算和推理预算。对“未来信息价值”和“可部署性能”分别使用固定头诊断与各自公平训练的结果，避免用一个表混合两种解释。

### M8. 动作翻转的配对单位不严谨

- **位置：**“动作翻转的修正与伤害”第 246--264 行。
- **问题：** 两个策略在第一次动作不同后会访问不同状态，后续逐步动作无法继续严格配对。“相同 episode”只能保证相同初始任务，不等于相同决策状态。当前四类还混合 episode 级成功和 step 级 flip，未定义一个 episode 多次翻转如何计数；“未翻转”的 $\Delta$SR/$\Delta$SPL 也需要固定随机性才有意义。
- **可执行修复：** 拆成两种分析：一是同一初始 episode、同一 simulator seed 的 episode-level 配对，按“是否曾翻转/首次分歧”统计终局变化；二是在同一记录状态上离线计算 base 与 lookahead 的 one-step counterfactual action，仅分析局部翻转。定义分母、多次翻转归属和随机控制；对成功用配对比例检验或置信区间，对 SPL 用配对/场景聚类 bootstrap。不要把 episode 结果差异表述为单次翻转因果效应。

### M9. 现有一步诊断缺少分母和定义，“链路稳定”解释偏强

- **位置：**“q1 来源与预测视野长度”第 244 行；讨论第 280 行；`evidence_bank.md` E10。
- **问题：** q0/q1 请求成功率 100%、future-valid 46.6%--49.6%、flip rate 0.17%--0.29% 没有样本数、分母、checkpoint 对应关系和区间。请求成功只说明调用未失败，future-valid 约一半表明可用候选仍有限，不能单独推出预测数值可靠或“推理链稳定”。
